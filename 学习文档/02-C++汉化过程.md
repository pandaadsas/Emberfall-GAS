# 02 - C++ 汉化过程记录（AI 已完成的部分）

> 本项目的 C++ 汉化由 AI 完成并已提交 git。本文档记录**做了什么、怎么做的、边界在哪里**，
> 便于你复查、续做蓝图侧汉化（见 `03-蓝图与资产汉化指南.md`），或将来新写代码时沿用同一套约定。

---

## 一、汉化范围与边界

### 已汉化（C++ 侧全部）
1. **代码注释**：全部 `.h` / `.cpp` 里的 `//` 行注释与 `/* */` 块注释 → 简体中文
   - 包括 UPROPERTY / UFUNCTION 上方的说明注释——它们会显示为 UE 编辑器 / Rider 悬停 tooltip，所以**编辑器悬停提示也一并变成中文了**
2. **游戏内技能描述文本**：C++ 里的 `GetDescription()` / `GetNextLevelDescription()` 富文本字符串（火弹术 / 火焰爆发 / 奥术碎片 / 电击），运行时显示在技能菜单 UI 上
3. **编译验证**：汉化后全量编译，零错误零警告

### 有意不汉化（保持英文/原样）
| 对象 | 原因 |
|---|---|
| `FName("...")`、`FGameplayTag` 字符串（如 `Damage.Fire`、`Abilities_Status_Equipped`） | 代码契约：C++/蓝图/资产三处引用，改名全线崩 |
| `UE_LOG` 的 `TEXT("...")` 日志内容 | 部分已中文化（告警类），日志属于调试信息不是游戏内容 |
| 曲线表行名（`ArmorPenetration` 等） | `FindCurve(FName(...))` 按 名字查找，是契约 |
| Actor Tag（`"Player"` / `"Enemy"`）、黑板键（`"Stunned"` 等） | C++ 与蓝图/AI 双向引用 |
| Socket 名（`TipSocket`）、碰撞通道（`ECC_Target`）、Profile 名 | 引擎查找契约 |
| 类名 / 函数名 / 变量名等标识符 | 代码本身不翻译（重命名会破坏蓝图反射与序列化） |
| `//TODO:` 前缀 | 保留待办语义 |
| 被注释掉的代码行（如 `//InitSlotStatus();`） | 那是代码不是注释 |

## 二、翻译原则（可复用的约定）

1. **只动注释文字，不动注释标记**：`//`、`/* */`、缩进、行尾结构原样保留，diff 干净、可 grep 审查。
2. **富文本标签原样保留**：`<Title>`、`<Small>`、`<Damage>`、`</>` 等只翻标签之间的文字；`%d` / `%.1f` 占位符的位置、数量、顺序与 Printf 参数严格一一对应——中文语序需要调整时**改写句子迁就参数顺序**，而不是移动参数（否则运行时错位）。
3. **术语表统一**（全项目一致）：

   | 英文 | 中文 |
   |---|---|
   | attribute | 属性 |
   | capture / captured | 捕获 |
   | debuff | 减益 |
   | cooldown | 冷却 |
   | mana cost | 魔法消耗 |
   | gameplay effect | GameplayEffect（保留，引擎术语） |
   | prediction key | 预测键 |
   | replicated / replication | 复制（网络复制） |
   | stack | 叠层 |
   | radial damage | 径向伤害 |
   | knockback | 击退 |
   | death impulse | 死亡冲量 |
   | highlight | 高亮 |
   | checkpoint | 存档点 |
   | loot tier | 掉落等级 |
   | widget controller | 控件控制器 |
   | view model | 视图模型 |
   | spell menu / attribute menu | 技能菜单 / 属性菜单 |
   | blackboard / behavior tree | 黑板 / 行为树 |

4. **区块标记保留标识符**：如 `//** 战斗接口（ICombatInterface）**//`——说明文字中文化，类型名保留方便跳转。

## 四、实施方式与质量保障

1. **分批并行**：按目录分 5 批（火系技能 / 其余能力 / GAS 核心 / 角色玩家 AI / UI-Game-Actor），每批独立处理。
2. **编辑工具约束**：只用"读取 + 精确替换"的编辑方式，不做整文件重写，避免编码/行尾被改坏（全部文件保持 UTF-8）。
3. **改动即校验**：每批完成后用 `git diff` 抽查，确认改动只落在注释与描述字符串内。
4. **编译兜底**：汉化结束后全量重编译——注释写坏（如破坏 `*/` 配对）会直接暴露为编译错误；描述字符串只改标签内文字，格式参数未动。
5. **残留扫描**：用脚本级 grep 扫描"连续英文单词的注释行"做收尾清查，防止漏网。

## 五、你自己复查的方法

```bash
# 1. 看本阶段的全部改动（应只包含注释与描述字符串）
git log --oneline          # 找到汉化相关提交
git show <hash> --stat     # 涉及文件清单

# 2. 扫描残留英文注释（连续两个以上英文单词的注释行）
grep -rn -e "//[A-Za-z]\{3,\}[ ]\+[A-Za-z]\{3,\}" Source/Dura --include="*.h" --include="*.cpp"

# 3. 编译验证
tools\Build_DuraEditor.bat
```

在 Rider 里也可以用 `//\p{Lu}\w+ \w+` 正则对注释做全局搜索复查。
