# 04 - Git 备份与恢复入门（写给项目作者自己）

> 本项目从初始化开始就在用 git 做版本管理（提交账号 panda）。
> 这份文档教你：git 是什么、怎么"存档"、怎么"读档"，以及 AI 是怎么修改蓝图的。

---

## 一、AI 是怎么"看到并修改"蓝图的？

蓝图 `.uasset` 是二进制文件，文本编辑器打开是乱码，所以 AI **不是**像人一样打开编辑器看画面改的，而是：

1. 用 **UE 自带的 Python 接口**驱动引擎本体：`UnrealEditor.exe Dura.uproject -ExecutePythonScript=脚本.py`（等于开了一个自动操作的编辑器）
2. 脚本通过引擎 API 读写字节产内部的数据：TextBlock 的 `Text`、Font 的回退链、DataTable 的行、CDO 上的标签……
3. 每改一处**读回验证**，全部完成后调用引擎保存——效果和你在编辑器里手动改完全一样
4. 改完用 `git commit` 提交，于是"改动前的状态"永远留在历史里，随时可恢复

**边界**：AI 看得到蓝图的结构化数据（控件、文本、属性、图表列表），但看不到"运行起来的画面长什么样"——所以字体效果、布局是否正常，最后需要你人眼验收。

## 二、git 的三个核心概念（游戏存档类比）

| git 概念 | 类比 | 一句话解释 |
|---|---|---|
| 仓库 (repository) | 整个游戏的存档系统 | 项目根目录的 `.git` 文件夹，记录全部历史 |
| 提交 (commit) | 一个存档点 | 把当前所有文件的状态永久记录下来，附一句说明 |
| 标签 (tag) | 给某个存档起名字 | 比如 `汉化前快照`，以后可以按名字读档 |

你的项目现状：`Content` 下 1025 个资产全部被 git 跟踪（`.gitignore` 排除了 Binaries/Intermediate/Saved 等生成物），所以**每次 commit 都是一份完整的蓝图+资产备份**。

## 三、日常操作：三个场景五条命令

在项目根目录打开终端（Git Bash 或 CMD 都行），或者直接用 Rider/VSCode 里的 git 图形按钮。

### 场景 1：我改了一堆东西，想存档（最常用，每天可多次）

```bash
git add -A                       # 把所有改动放进"待存档"区
git commit -m "写这次改了什么"     # 存档，引号里是给未来自己看的说明
```

### 场景 2：我改坏了，想恢复

```bash
# 只恢复某一个文件（最常用，最安全）
git restore "Content/Blueprints/UI/SpellMenu/WBP_SpellMenu.uasset"

# 恢复到某个存档点之前的某个文件
git restore --source 汉化前快照 -- "Content/路径/资产.uasset"

# 整个项目回到某个存档点（危险！之后的所有改动都会消失，先确认）
git reset --hard 汉化前快照
```

### 场景 3：做危险操作之前，先起个名字

```bash
git tag 这个操作前的快照          # 当前状态被打上标签
git tag -l                       # 列出所有标签
git log --oneline                # 查看所有存档历史（一行一条）
```

## 四、推荐习惯（本项目验证过的做法）

1. **小步提交**：改一小批 → 编译/验证 → commit。本项目每个修复批次都是这样提交的，出问题能精确回到"哪一步之前"。
2. **大动作前打标签**：改蓝图/资产这种二进制文件前，先 `git tag xxx前快照`，因为二进制没法像代码那样逐行 diff，整文件恢复是唯一后悔药。
3. **commit 说明写清楚"为什么"**：中文、一句话，写动机而不是流水账（本项目提交记录就是范例，`git log` 可以翻）。
4. **二进制大文件的额外保险**：git 之外再做一次 zip（本项目做过 `D:\UE_Project\backup\Dura_Content_backup_20260829.zip`），防 git 仓库本身出意外。

## 五、AI 帮你操作 git 的方式

AI 在这个项目里的所有修改都是"改一部分 → 验证（编译/读回）→ `git commit`"循环，用的是你的本地 git 和 panda 账号。你可以随时：

```bash
git log --oneline        # 看它做过什么
git show <提交号> --stat  # 看某次提交动了哪些文件
git diff HEAD            # 看当前还没提交的改动
```

发现不想要的改动：`git restore .`（丢弃全部未提交改动，谨慎）或按文件恢复。
