# 03 - 蓝图与资产汉化指南（供手动操作）

> C++ 侧的汉化（注释 + 游戏内技能描述文本）已由 AI 完成并提交，见 `02-C++汉化过程.md`。
> 本文档是**你自己操作**的手册：把 Content 目录下蓝图、数据资产、控件里的英文界面文本改成中文。

---

## 一、先搞清楚：哪些能改，哪些不能改

| 对象 | 能否直接改 | 说明 |
|---|---|---|
| WBP 控件里的 Text Block 显示文本 | ✅ 随便改 | 纯显示，不影响逻辑 |
| 蓝图节点的 Comment 气泡注释 | ✅ 随便改 | 纯注释 |
| 蓝图内自定义事件/函数的**显示名**（DisplayName） | ✅ 可改 | 只影响编辑器显示 |
| 蓝图变量/函数的**内部名** | ⚠️ 用右键 → Rename | 蓝图会自动更新同资产内引用；跨资产引用（接口函数、蓝图函数库）要全局确认 |
| C++ 暴露的 UFUNCTION/UPROPERTY 名 | ❌ 不能在蓝图侧改 | 由 C++ 决定，改名要回 C++（本项目已定稿，不要再动） |
| DataTable 的**行名**（RowName） | ❌ 千万别改 | `MessageWidgetDataTable` 的行名就是 GameplayTag 字符串（如 `Message.HealthPotion`），C++ 按 Tag 查行，改了查不到 |
| DataTable 的**行内文本列** | ✅ 可改 | 改的是显示内容 |
| 数据资产（DA_xxx）里的 FText/FString 字段 | ✅ 可改 | 如 AttributeInfo 的名称/描述字段 |
| GameplayTag 名（如 `Abilities.Fire.FireBolt`） | ❌ 不能改 | C++/蓝图/资产三处引用，动了全线崩 |
| 动画 Montage 的 Section 名、Socket 名 | ❌ 不能改 | C++ 按名字取（如 `TipSocket`） |

**一条铁律**：凡是 C++ 代码里 `FName("...")` / `FGameplayTag` / `FindCurve(FName(...))` 能看到的字符串，就是"契约"，不能在资产侧改名。

## 二、汉化对象清单（本项目实际要改的地方）

按项目结构，需要动手的资产大致是：

1. **WBP 控件**
   - `WBP_DuraOverlay`（主界面）：按钮提示、面板标题等静态文本
   - `WBP_SpellMenu`（技能菜单）：标题、列头（"Name"/"Level"/"Cost"之类）、提示文字
   - `WBP_AttributeMenu`（属性菜单）：属性名显示行、关闭按钮
   - `WBP_LoadScreen`（读档界面）：Load/Save/Delete/Play 按钮文字、槽位提示
   - `WBP_HUD` 相关子控件
   - 技能球/属性球上的静态文字
2. **数据资产**
   - `DA_AttributeInfo`：每个属性的 Name / Description 字段（Strength → 力量 等）
   - `DA_AbilityInfo`：如有显示字段
   - `DA_CharacterClassInfo`：无文本字段，跳过
3. **DataTable**
   - `MessageWidgetDataTable`：每行 Message 列的富文本内容（`<Default>You picked up a Health Potion</>` 这类 → 中文），**行名不要动**
4. **蓝图节点注释**：各 Ability 蓝图（BP_FireBolt 等）与角色蓝图里散落的英文注释

## 三、逐类操作步骤

### 3.1 WBP 控件文本
1. 双击打开 WBP → 在 Designer 里选中 Text Block
2. Content 面板 → Text 字段直接输入中文
3. 如果 Text 绑定的是函数/ViewModel（Bind 项），去改绑定函数返回的字符串或 ViewModel 字段
4. 注意字体：中文字符需要字体资产含 CJK 字形。默认 `Roboto` 没有中文，会显示豆腐块。**必须先做这一步**：
   - 导入一个含中文的字体（如"思源黑体 SourceHanSans"或 Windows 自带 `C:\Windows\Fonts\msyh.ttc` 微软雅黑）
   - 内容浏览器导入 .ttf/.ttc → 生成 FontFace → 组合到 Font 资产（或直接用 Composite Font 加 Fallback）
   - 全局替换各 WBP 里的 Font 引用（或项目设置里改默认字体）

### 3.2 蓝图注释
- 选中 Comment 框直接改；空白处按 `C` 新建注释
- 技能蓝图（BP_FireBolt、BP_FireBlast、BP_ArcaneShards、BP_Electrocute 等）里通常有课程老师留的分段注释（Initialize、Launch、OnHit 等），逐个改

### 3.3 数据资产 DA_AttributeInfo
- 打开 → 逐条 Element → 改 AttributeName / AttributeDescription
- 这些字段如果显示为灰色（只读），说明是 C++ FText 且由 Metadata 控制——本项目该字段可编辑，正常改即可

### 3.4 DataTable 文本列
- 双击打开 → 找文本列（Message / Tooltip 等）→ 逐行改
- 富文本标签 `<Default>...</>`、`<Title>...</>` 保留，只翻标签之间的字

## 四、要不要走 UE 本地化体系（多语言）？

两种路线，按需选：

### 路线 A：直接改文本（推荐，当前阶段）
就是上面第三节的操作。优点：半小时内做完、所见即所得；缺点：将来想出英文版要重做一遍。

### 路线 B：Localization Dashboard（要出多语言时再上）
1. 编辑器 → Tools → Localization Dashboard
2. 新建 Localization Target（Game），Gather Text：
   - 它会自动收集**蓝图里所有 FText**（Text Block、数据资产 FText 字段）
   - C++ 侧只有被 `LOCTEXT/NSLOCTEXT` 包裹的文本才会被收集（本项目 C++ 文本已直接中文化，不在收集范围）
3. 点 "Gather Text" 生成 .archive → 填写中文翻译列
4. "Compile Text" 生成 .locres → PIE 里 Language 切到 zh-Hans 验证
5. 项目设置 → Packaging 里把 `zh-Hans` 加入 Cultures To Stage，并开启 "Internationalization Support"

> 建议：先走路线 A 把游戏做完；等真的要双语发行时，把路线 A 改过的文本再搬进本地化体系（搬运工作量不大，文本内容已经在那里了）。

## 五、验证清单

- [ ] 字体已含中文字形（否则全是 □□□）
- [ ] PIE 运行：主界面 / 技能菜单 / 属性菜单 / 读档界面 无英文残留
- [ ] 拾取道具时飘出的提示（MessageWidgetDataTable）是中文
- [ ] 技能悬停描述是中文（这部分来自 C++，应已是中文——若仍是英文说明 C++ 描述被蓝图覆盖，检查 WBP 是否本地复制了一份文本）
- [ ] 修改过的每个资产保存后，git 提交（Content 二进制文件无法 diff，务必小步提交、写清改了哪个资产）

## 六、常见坑

1. **改了字段名而不是字段值**：在数据资产里改的是"显示文本"，不是变量名，别用 Rename。
2. **富文本标签被删**：`</>` 闭合标签删掉后整段样式失效，复制时连标签一起保留。
3. **字体只改了一处**：WBP 有多个 Text Block 时逐个检查 Font 引用；有的子控件是嵌套 WBP，要到最里层改。
4. **PIE 缓存**：改完 DataTable 后如果 PIE 里没变化，先 Re-save 该表或重启 PIE。
5. **别开机器翻译插件批量覆盖**：会把 GameplayTag 显示名一起改坏，逐资产手动更稳。
