## 一、UE 5.8 弃用 API 适配（升级后必须处理的部分）

| 旧写法（5.3） | 新写法（5.5+） | 涉及位置 |
|---|---|---|
| `UGameplayAbility::AbilityTags` 直接访问 | `GetAssetTags()` | 所有能力类 |
| `FGameplayAbilitySpec::DynamicAbilityTags` 直接访问 | `GetDynamicSpecSourceTags()` | `DuraAbilitySystemComponent` |
| `AActor::NetUpdateFrequency` 直接赋值 | `SetNetUpdateFrequency()` | `DuraPlayerState` |
| `UGameplayEffect::StackingType` 直接赋值（5.7 转私有，setter 未导出） | 保留直接赋值 + `PRAGMA_DISABLE_DEPRECATION_WARNINGS` 压警告，注释说明升级路径 | `DuraAttributeSet.cpp` Debuff() |

**经验**：UE 升级后第一件事是全量重编译收集警告，弃用 API 几乎都会以 deprecation warning 形式暴露，逐条处理即可。

## 二、UE 5.8 容器语义变化（最容易踩的隐形坑）

- `TMap::operator[]` 对**缺失键**是断言语义（FindChecked），不再宽容。
  - `DuraAttributeSet.cpp`：`DamageTypesToDebuffs[DamageType]` → `FindRef(DamageType)` + 无效 Tag 安全返回
  - `ExecCalc_Damage.cpp`：`DamageTypesToResistances[DamageType]` → `FindRef` + 显式 continue
  - `CharacterClassInfo.cpp`：`CharacterClassInformation.FindChecked()` → `Find()` 回退 Warrior + `UE_LOG` 告警
  - `DuraGameModeBase.cpp`：`Maps.FindChecked()` → `Find()` + 告警早退
- **原则**：运行时配置（数据资产、TMap 配置项）驱动的查找一律用 `Find/FindRef` + 降级路径，把"策划没配"当成正常分支处理，而不是崩溃。

## 三、隐藏 Bug 修复（原课程代码就存在）

### 3.1 内存/委托安全
- **径向伤害悬空 lambda**（`ExecCalc_Damage.cpp`）：给受害者的 `OnDamageDelegate` 绑定了捕获栈变量的 lambda，径向伤害结算后从未移除——后续任何一次广播都会执行悬空指针（内存破坏）。修复：记录 `FDelegateHandle`，结算后立即 `Remove`。
- **Debuff 动态 GE 内存泄漏**（`DuraAttributeSet.cpp` Debuff()）：`FGameplayEffectSpec` 堆分配后从未释放 → 改为栈上对象。
- **冷却任务解绑遗漏**（`WaitCooldownChange.cpp`）：`EndTask()` 只解绑了 TagEvent，漏掉 `OnActiveGameplayEffectAddedDelegateToSelf`。
- **被动能力重复绑定**（`DuraPassiveAbility.cpp`）：InstancedPerActor 实例重复激活时 `AddUObject` 堆积 → 绑定前 `RemoveAll(this)`。
- **眩晕标签重复注册**（`DuraCharacter.cpp`）：`OnRep_PlayerState` 每次触发都注册一遍 → 先 `RemoveAll(this)` 再注册。
- **死亡定时器悬挂**（`DuraCharacter.cpp`）：裸 lambda 定时器 → `FTimerDelegate::CreateWeakLambda`。

### 3.2 复制粘贴错误
- `OnRep_Vigor` 误写 `Resilience`（`DuraAttributeSet.cpp`）
- `checkf` 断言条件写反且检查了错误的键（`ExecCalc_Damage.cpp`：应检查 `ResistanceTag`，原代码检查 `DamageTypeTag` 恒通过，断言从未生效）
- `MVVM_LoadScreen.cpp` 连续两次 `SetPlayerLevel`（重复行）

### 3.3 输入/状态屏蔽缺失（GAS Tag 屏蔽体系）
- 眩晕 debuff 会添加 `Player_Block_InputPressed / Player_Block_CursorTrace` 等屏蔽 tag，但：
  - `AbilityInputTagPressed` 没有 InputPressed 检查（Released/Held 都有）→ 眩晕时仍能按键放技能
  - `MouseTrace` 没有 CursorTrace 检查 → tag 形同虚设，且阻塞期间 `hitResult` 保留过期命中数据
- 修复后四个输入入口 + 鼠标寻迹的屏蔽行为完全一致。

### 3.4 逻辑错误
- **off-by-one**：掉落/格挡/暴击/击退概率 `RandRange(1,100) < X` → `<= X`（`<` 使 100% 概率也有 1% 失败，整数概率整体偏移 1%）
- **Move 语义误用**（`PointCollection.cpp`）：把 `OutActors`（出参）当 `ActorsToIgnore`（入参）传，忽略列表实际为空；且生存者查询放在循环内每点执行一次 → 提出循环，结果真正用于 `AddIgnoredActors`
- **服务端判断与权限检查顺序**：`SaveProgress` 的 `HasAuthority` 检查位于写档中途 → 提前到函数开头
- **失效目标扩散中心**（`DuraBeamSpell.cpp`）：`MouseHitActor` 已销毁时直接解引用 → `IsValid` 失败退化用鼠标命中点
- **SpellGlobeSelected 装备等待**、`MaxNumProjectiles` 死配置（从未生效，删除）等

## 四、判空加固（崩溃面清理）

原则：**所有从 ActorInfo / Owner / Cast / 数据资产 拿到的指针，解引用前必须确认**。

覆盖位置（部分）：
- `GetAvatarActorFromActorInfo()`：DuraFireBlast / DuraFireBolt / DuraProjectileSpell / DuraSummonAbility / DuraDamageGameplayAbility / DuraPassiveAbility
- `GetAvatarActor()`：DuraAbilitySystemComponent（UpgradeAttribute / ServerUpgradeAttribute / ServerSpendSpellPoint）
- 数据资产：LevelUpInfo / AbilityInfo / MessageWidgetDataTable / CharacterClassInfo / BehaviorTree / Blackboard
- 生成物：`SpawnActorDeferred` / `SpawnActor` 返回值（FireBall / Projectile / MagicCircle）
- SpecHandle：`MakeOutgoingSpec` 后 `IsValid()` 再 `*Data`
- `DuraAbilitySystemLibrary::IsNotFriend`：任一 Actor 失效按"敌对"处理（弹道判定不崩）
- `ApplyDamageEffect`：Source/Target ASC 入参判空（公共蓝图接口）
- `DuraCharacter::InitAbilityActorInfo`：`check(ASC)` 从解引用之后移到赋值之后（原 check 形同虚设）

## 五、蓝图暴露正确性（UHT 语义）

- `SetDeathImpulse / SetKnockbackForce / SetRadialDamageOrigin` 缺少 `UPARAM(ref)`：UHT 把非 const 引用参数当**输出 pin**，蓝图节点拿不到传入的 handle，调用静默无效。补齐后与同组其余 setter 一致。
- `DebuffNiagaraComponent::DebuffTag` 缺 `UPROPERTY` → 蓝图无法配置，补 `EditDefaultsOnly`。
- `Dura.Build.cs`：`GameplayTags` 从 Private 移入 Public 依赖（公开头文件引用其类型）。
- **改签名前必查蓝图引用**：项目里所有拼写重命名（`OverlamppedComponent`、`DoNotRmove`、`OutAddditionalTargets`、`AdditianalTargetDied` 等）都先 `grep` 过 Content 下的 .uasset 名字表确认无引用才执行。

## 六、日志规范

- 项目内唯一日志分类 `LogDura`（`DuraLogChannels.h`），`LogTemp` 全部替换。
- 降级路径（配置缺失、地图未注册）用 `UE_LOG(LogDura, Warning, ...)` 告警而不是静默失败。

## 八、后续可优化点（有意留下，供继续练手/优化）

> 以下是**性能与架构层面**的改进空间。本轮按约定只做"商业正确性"，性能刻意未动，避免过早优化。按收益/难度排序列出：

### 高收益
1. **伤害数字组件对象池**（`DamageTextComponent`）：目前每次跳字都 `NewObject + RegisterComponent` 再销毁。AOE 命中多目标时组件分配/销毁开销大。建议做一个组件池（隐藏复用 + 定时归还）。
2. **`BTService_FindNearestPlayer` 每帧 `GetAllActorsWithTag`**：全场景 Actor 遍历 + Tag 匹配，AI 数量多时是 O(N*M)。建议：a) `NextRequiredInterval` 降频（如 0.2s）；b) 或用 `GameplayTag` 聚合器/Team 注册表事件驱动维护最近玩家缓存。
3. **动态 Debuff GE 缓存**（`DuraAttributeSet::Debuff()`）：每次结算都 `NewObject<UGameplayEffect>` 动态拼 GE。可以按 (DamageType) 预构建并缓存 GE 类，运行时只改 SetByCaller 数值。
4. **`AbilityInfo::FindAbilityInfoForTag` 线性查找**：调用频率不低（UI 每次技能状态变化都查）。建议构建时（PostLoad/初始化）把 `Tag → Index` 建成 TMap。

### 中收益
5. **鼠标寻迹降频**（`DuraPlayerController::MouseTrace`）：每 Tick `GetHitResultUnderCursor` + 高亮切换。可以隔帧执行，或高亮状态变化时才调用接口（目前重复调用 Highlight）。
6. **属性复制条件收紧**：`DOREPLIFETIME_CONDITION_NOTIFY(..., COND_None, ...)` 全部对所有人复制。敌人属性可考虑 `COND_None` 保留（战斗需要），玩家私有属性（XP/点数）确认走 Owner 通道。
7. **WidgetController 全量广播**：`AbilityInfoDelegate` 每次广播整个 `FDuraAbilityInfo` 结构体，UI 层大量刷新。可按需差量更新（只广播变化的字段/槽位）。
8. **`PointCollection::GetGroundPoints`**：已把生存者查询提出循环；进一步可换成单次 `SweepMultiByChannel` 或预烘焙地面高度采样。

### 低收益/长期
9. **字符串构造**：技能描述 `FString::Printf` 每次悬停都重新拼接 → 可按 (AbilityId, Level) 缓存，或在 UI 层做脏标记。
10. **网络预测深化**：`TargetDataUnderMouse` 已有正确预测键；进一步可给移动/普攻加更完整的预测与回滚策略。
11. **构建速度**：开启 Unity Build 收益权衡、UbA 分布式缓存（当前已是 local executor）。
12. **资产级优化**：LOD、Niagara 实例化、共享材质实例（需在编辑器内做，属资产工程）。
