# 13 · 面试考点速查手册 —— 高频问题与标准答法

> **用法**：面试前最后一晚过一遍；每题给「一句话答法」+「展开要点（带项目出处）」。**所有答案都来自本项目真实代码**——面试时说"我在项目里是这样做的"比背概念高一档。
> 星级 = 被问概率。

# A. GAS 核心（被问概率 ★★★★★）

## A1. ASC 应该放在 Pawn 还是 PlayerState 上？

- **一句话**：多人游戏玩家放 PlayerState（数据跨重生存续、全端可见），单人/AI 放 Pawn（简单直接）。
- **展开**（02 篇）：本项目两种都实现——玩家 ASC 在 `DuraPlayerState`（Pawn 只是引用它），敌人 ASC 在 `DuraEnemy` 自身。玩家的 OwnerActor=PlayerState、AvatarActor=Character（`InitAbilityActorInfo(PS, this)`），敌人两者都是自己。这个区分决定了所有后续系统怎么拿 ASC（统一走 `IAbilitySystemInterface`/`UAbilitySystemBlueprintLibrary::GetAbilitySystemComponent`）。

## A2. ASC 的复制模式 Full / Mixed / Minimal？

- **一句话**：Full 全量复制（单人）、Mixed GE 只复制给拥有者客户端+Tag 复制给所有人（玩家）、Minimal GE 不复制只复制 Tag（AI）。
- **展开**（02 篇）：本项目玩家用 Mixed + **`SetNetUpdateFrequency(100)`**（PlayerState 默认 0.1 会让冷却条卡顿——Mixed 模式要求 Owner 高频同步，GAS 官方文档的要求）；敌人 Minimal 省带宽。
- **追问**：Mixed 模式下客户端怎么知道技能列表？——Spec 数组复制 + `OnRep_ActivateAbilities` 里广播 AbilitiesGiven（06 篇）。

## A3. 一次技能激活的完整流程？（客户端按键 → 服务器执行）

- **一句话**：输入带 InputTag → ASC 遍历 Spec 匹配 DynamicTags → TryActivateAbility（CanActivate 检查 Cost/Cooldown/Block）→ 携带预测键激活 → 技能内异步任务 → 服务器验证。
- **展开**（03/06 篇）：Pressed/Held/Released 三种输入路由不同（Held 才 TryActivate）；`InvokeReplicatedEvent(InputPressed, Handle, 预测键)` 把技能运行中的输入事件同步给服务器技能实例；`FScopedAbilityListLock` 保护遍历期间的 Spec 数组。

## A4. 客户端技能怎么拿到鼠标目标？（TargetData/预测）

- **一句话**：客户端 AbilityTask 里做光标 Trace → 打包 `FGameplayAbilityTargetDataHandle` → `ServerSetReplicatedTargetData(SpecHandle, 激活预测键, Data, Tag, ScopedPredictionKey)` 发服务器 → 服务器按（Handle+预测键）路由到同一任务实例 → 两端同时广播 ValidData。
- **展开**（06 篇）：接收端 `AbilityTargetDataSetDelegate` 注册 + `CallReplicatedTargetDataDelegatesIfSet` **竞态兜底**（数据可能先于 Activate 到达）+ 未到则 `SetWaitingOnRemotePlayerData`；收到后 `ConsumeClientReplicatedTargetData` 防重放。

## A5. 伤害是怎么算出来的？（GE → ExecCalc → 属性）

- **一句话**：技能构造 FDamageEffectParams → Library::ApplyDamageEffect 生成 Spec（SetByCaller 注入伤害/Debuff，Context 注入机制数据）→ GE 的 Executor 调 ExecCalc_Damage → 捕获双方属性 → 抗性/径向/格挡/护甲/暴击五段修正 → 输出加到元属性 IncomingDamage → PostGameplayEffectExecute 统一结算。
- **展开**（05/04 篇）：五段公式细节；**为什么用元属性**（结算集中、顺序正确、Debuff 周期伤害复用同一漏斗、计算器无副作用权限）；ExecCalc 捕获定义三要素（AttributeToCapture/Source|Target/**bSnapshot=false 实时**）。

## A6. 格挡/暴击信息怎么传到客户端 UI？

- **一句话**：继承 `FGameplayEffectContext` 加自定义字段 → 重写 GetScriptStruct/Duplicate/NetSerialize 三件套 → `TStructOpsTypeTraits` 声明 WithNetSerializer → ini 替换 `UAbilitySystemGlobals::AllocGameplayEffectContext` → NetSerialize 用**位掩码**（有值才传）。
- **展开**（01 篇）：Duplicate 必须深拷贝 HitResult；NetSerialize 收尾 `AddInstigator` 重建 InstigatorASC；**陷阱**：SerializeBits 的位数必须 ≥ 最大置位位数（本项目第 19 位有 off-by-one 隐患——能主动指出这种问题是高分项）。

## A7. 属性怎么派生？（MMC）Pre/Post 回调时机？

- **一句话**：MMC 捕获属性（bSnapshot 决定实时还是快照）+ 从 Context 的 SourceObject 查等级 → 返回公式值（MaxHealth=80+2.5×Vigor+10×Level）。
- **三回调**（04 篇）：`PreAttributeChange`（只准 Clamp NewValue，改别的会递归）、`PostGameplayEffectExecute`（GE 结算漏斗）、`PostAttributeChange`（Base 变化后，本项目用它+bool 标记实现"升级补满血蓝"）。

## A8. 冷却怎么实现？UI 怎么知道剩余时间？

- **一句话**：Cooldown GE 的 GrantedTags 带冷却 Tag（挂上=在 CD）；`UWaitCooldownChange` 双监听——**GE 添加委托**（拿 Spec 查剩余秒数，广播 CooldownStart）、**Tag 计数事件**（归零广播 CooldownEnd）。
- **展开**（06 篇）：为什么不用 Tag 事件算开始（拿不到剩余秒数）；按 Tag 查询 `FGameplayEffectQuery::MakeQuery_MatchAnyOwningTags` + 取剩余时间最大值；EndTask 必须对称解绑。

## A9. Cooldown / Cost GE 与技能的关系？

- **一句话**：GA 类上有 `CostGameplayEffectClass`/`CooldownGameplayEffectClass` 两个槽；激活检查不过不放行。C++ 描述系统用 `GetDefaultObject()` 读 GE 的 Modifiers 取"显示用消耗/冷却值"（06 篇 GetManaCost/GetCooldown）——**描述与实际同源不撒谎**。

## A10. Native Tag 为什么要启动时注册？放哪？

- **一句话**：GAS 生命周期早于第一帧（ASC 初始化/StartupGE 都要用 Tag），注册点选 `UAssetManager::StartInitialLoading()`（ini 配子类）——引擎最早的全局初始化钩子（01 篇）。代码要当标识符用的 Tag 必须 Native（编译期拼写检查）。

# B. UE 框架与网络（★★★★★）

## B1. Pawn / Controller / PlayerState / GameMode / GameInstance / GameState 的职责与生命周期？

| 类 | 生命周期 | 职责 | 本项目化身（02/09 篇） |
|---|---|---|---|
| Pawn | 可销毁重生 | 临时身体 | DuraCharacter/DuraEnemy |
| Controller | 跨身体 | 灵魂（玩家意图/AI 决策） | 输入枢纽 PC / AIController |
| PlayerState | 跨身体、全端可见 | 户口档案 | ASC+属性+等级+XP |
| GameMode | 每张图、仅服务器 | 规则/存档/出生点 | 数据资产+存档 CRUD |
| GameState | 每张图、全端 | 全局游戏状态 | （本项目未定制——诚实说"项目里没用上，但知道该放什么"） |
| GameInstance | 整个进程 | 跨图会话数据 | 槽位名/索引/出生点 Tag |

## B2. 客户端玩家的 ASC 初始化时机？为什么有两条轨道？

- **一句话**：服务器走 `PossessedBy`（Possession 是服务器概念），客户端走 `OnRep_PlayerState`（PlayerState 复制到位的 RepNotify）——两轨汇合到同一个 `InitAbilityActorInfo()`（02 篇）。
- **加分**：重复调用防护（Tag 事件先 `RemoveAll(this)` 再注册）；客户端没有"授予技能"时刻，靠 Spec 数组 OnRep 感知初始化完成。

## B3. Replicated / ReplicatedUsing / REPNOTIFY_Always？

- **一句话**：Replicated 纯复制；ReplicatedUsing 加 OnRep 回调；`DOREPLIFETIME_CONDITION_NOTIFY(..., COND_None, REPNOTIFY_Always)` 让"值没变也通知"——**属性必用 Always**（读档恢复相同血量时 OnChanged 不触发 → UI 不刷新，GAS 著名坑，04 篇）。
- **OnRep 属性宏**：`GAMEPLAYATTRIBUTE_REPNOTIFY` 手动触发聚合监听——漏写则客户端属性变化委托（UI）全部静默失效。

## B4. 弹丸的命中表现如何保证每台机器都播且不重复？

- **一句话**：客户端 Overlap 时预测播 OnHit 置 bHit；服务器权威结算后 Destroy → 销毁复制触发各端 `Destroyed()` → `if(!bHit && !HasAuthority()) OnHit()` 兜底补播（超时自毁/打中无 ASC 物体等"从未走伤害分支"的场景）（12 篇）。
- **加分**：`SetReplicateMovement(true)` 单独于 bReplicates；MovementComponent 驱动运动。

## B5. 射线/重叠检测的通道怎么配？（弹丸/瞄准/触发器）

- **一句话**：自定义 GameTraceChannel 用宏起语义名（ECC_Projectile/Target/ExcludePlayers，01 篇）；弹丸 QueryOnly+白名单 Overlap+ObjectType=ECC_Projectile（12 篇）；鼠标瞄准 ECC_Target、高亮 ECC_Visibility（03 篇）；触发器 QueryOnly+只对 Pawn Overlap（10/11 篇）。**ObjectType 是"我是谁"，Response 是"我对谁反应"，双向成对配置**。

## B6. 客户端 RPC 的四种类型与选择？

- **一句话**：Server（客户端→服务器，如 SpendSpellPoint）、Client（服务器→拥有者，如 ShowDamageNumber）、NetMulticast（服务器→全端，如死亡表现）、可靠/不可靠按重要性（死亡 Reliable、粒子 Unreliable）。
- **项目例**（02/03/06 篇）：MulticastHandleDeath（Reliable，一次性关键事件）；ClientEquipAbility 带 4 参回执（UI 要旧槽位）。

## B7. 断言宏 check / ensure / checkf 的选择？

- **一句话**：`check` 必崩（Debug/Dev 生效，Shipping 剔除）；`ensure` 可恢复+报错（Shipping 也跑但只报一次）；`checkf` 带格式化消息。**配置错误用 check 炸得早，运行环境合法缺失用判空降级**（本项目把 FindChecked 改成 Warn+回退 Warrior 的"断言降级"实践，07 篇）。

# C. UE Gameplay 常用系统（★★★★☆）

## C1. Enhanced Input 三件套与绑定陷阱？

- **一句话**：InputAction（语义键）/ InputMappingContext（键→IA 映射+优先级）/ TriggerEvent（Started/Triggered/Completed）；绑定在 `SetupInputComponent`（不是 BeginPlay）；**循环绑 Lambda 必须先拷贝循环变量再按值捕获**（`FGameplayTag Tag = Action.InputTag; [this, Tag]`——直接捕获成员是捕获 this，悬垂 UB，03 篇）。

## C2. 点击移动怎么做？（导航+样条）

- **一句话**：光标射线 → `FindPathToLocationSynchronously` 寻路 → 路径点填 `USplineComponent` → 每帧"最近投影点+切线方向 AddMovementInput"沿样条走 → 距终点 ≤ 接受半径停 → 手动输入打断（03 篇）。
- **加分**：终点修正为路径最后点；`IHighlightInterface::SetMoveToLocation` 让交互物微调落点；Held 拖动（直线）与 Released 寻路（绕障）的手感分工。

## C3. 行为树 Service 与 Task 的区别？黑板怎么被 C++ 共享？

- **一句话**：Task 干活返回成功失败，Service 伺候（按间隔 Tick 维护数据）；黑板是 AI 的共享内存——C++ 受击/眩晕/死亡写键（HitReacting/Stunned/Dead），服务/任务读键决策（10 篇）；`FBlackboardKeySelector` 让键成为资产配置。
- **加分**：索敌 Service 的反向 Tag 搜索（玩家搜敌人/敌人搜玩家，通用服务）；`GetAllActorsWithTag` 的性能账（间隔 Tick/大场景换 Perception）。

## C4. USaveGame 体系怎么设计存档？

- **一句话**：USaveGame 子类存 UPROPERTY；`SaveGameToSlot/LoadGameFromSlot` 按槽名+索引；**世界状态**用"接口+反射字节流"：`ISaveInterface`（ShouldLoadTransform/LoadActor）+ `UPROPERTY(SaveGame)` 字段 + `FObjectAndNameAsStringProxyArchive(ArIsSaveGame=true)` + Actor->Serialize（02/09/11 篇）。
- **加分**：PIE 前缀清洗（`RemoveFromStart(StreamingLevelsPrefix)`）；ActorName 匹配；"存根不存派生"（存四维主属性，MaxHealth 等读档重算）。

## C5. GameInstance 的用途？

- **一句话**：跨地图存续的会话单例——本项目放"当前槽位名/索引/出生点 Tag"，主菜单→关卡→死亡的全程靠它传递上下文（02/09 篇）。不用静态变量（生命周期由引擎管理、PIE 安全）。

## C6. Delayed Spawn：SpawnActorDeferred 为什么存在？

- **一句话**：先给"构造完成但 BeginPlay 未跑"的半成品 → 注入参数（弹丸的伤害 Params/敌人的等级职业）→ `FinishSpawning` 补完生命周期——**参数必须先于 BeginPlay 就位的场景唯一解**（06/10 篇）。Deferred 生成的 Pawn 要手动 `SpawnDefaultController`。
- **加分**：`ESpawnActorCollisionHandlingMethod` 三选（AlwaysSpawn/AdjustIfPossible/DontSpawnIfColliding）。

# D. UI 架构（★★★★☆）

## D1. 你的 UI 怎么和游戏数据解耦？（MVC）

- **一句话**：Widget（UUserWidget）只渲染；**WidgetController（UObject）**持有四件套（PC/PS/ASC/AS），`BindCallbacksToDependencies` 订阅游戏委托、`BroadcastInitialValue` 快照广播、`BlueprintAssignable` 委托喂给蓝图；HUD 是 Controller 的懒工厂（08 篇）。
- **加分**：装配五步顺序（CreateWidget → 造 Controller 并绑定 → SetWidgetController 触发蓝图接线 → BroadcastInitialValue → AddToViewport——数据先行展示殿后）；**先绑定后广播**的铁律。

## D2. MVC 与 MVVM 的区别？什么时候用哪个？

- **一句话**：MVC 手动委托（事件流复杂、GAS 场景）；MVVM `UMVVMViewModelBase` + `FieldNotify` 属性（`UE_MVVM_SET_PROPERTY_VALUE` 值变自动通知）+ UMG 绑定编辑器直连（表单型 UI，09 篇）。
- **项目例**：主界面/技能菜单走 WidgetController；存档槽位走 MVVM（3 个槽位 VM + 屏幕级 VM 管选中互斥）。

## D3. FieldNotify 是什么？

- **一句话**：UPROPERTY 加 `FieldNotify` specifier + Setter 里用 `UE_MVVM_SET_PROPERTY_VALUE`（值不变不通知）→ UMG 属性绑定自动刷新——属性级响应式，免手写委托（09 篇）。

## D4. 技能菜单的装备交互状态机？

- **一句话**：选中（SpellGlobeSelected 四分支推导状态）→ 花点（ServerSpendSpellPoint：Eligible→UnLocked→Level+1，MarkAbilitySpecDirty 复制）→ 装备两阶段（EquipButtonPressed 广播等待态 → 点槽位校验类型 → ServerEquipAbility 服务器裁决 → ClientEquipAbility 回执 → 双 Controller 广播刷新两块 UI）（06/08 篇）。
- **加分**：技能状态机四态（Locked/Eligible/UnLocked/Equipped）全存在 Spec 的 DynamicTags 里——单一数据源。

# E. C++ 语言与 UE 宏（★★★☆☆，追问重灾区）

## E1. 委托三兄弟怎么选？

- **一句话**：**非动态**（DECLARE_MULTICAST_DELEGATE，C++ only，快）/**动态**（DYNAMIC，蓝图可绑 BlueprintAssignable）/**单播**（DECLARE_DELEGATE，一对一）。
- **项目例**（02/06 篇）：OnDeath 用动态（蓝图要响应死亡）；OnASCRegistered 用非动态（纯 C++ 消费）；FForEachAbility 用单播当"遍历函数参数"。

## E2. Lambda 捕获的坑？

- **一句话**：循环里必须**先拷贝再按值捕获**（引用捕获循环变量悬垂，03/08 篇 `[this, Tag]`、`[this, Pair]`）；定时器/跨帧回调用 **WeakLambda**（死亡定时器 `CreateWeakLambda(this, ...)`，02 篇）；UObject 委托优先 AddUObject（GC 感知）。

## E3. 容器遍历中删除怎么办？

- **一句话**：**两段式**——先收集待删（委托句柄/Map 键）再统一删（EffectActor 的 ActiveHandlers 回收，11 篇）；GAS 遍历 Spec 用 `FScopedAbilityListLock` 防并发修改（06 篇）。

## E4. TMap 的 Find / FindRef / FindChecked？

- **一句话**：Find 返回指针（判空）、FindRef 返回值（缺省默认）、FindChecked 缺失断言——**开发期断言暴露配置错、Shipping 降级保运行**（07 篇回退 Warrior 实践）。

## E5. FString / FName / FText？

- **一句话**：FName 哈希不可变比较快（Tag 内部）；FString 可变拼接；FText 本地化显示（07 篇属性名用 FText）。

## E6. 成员函数指针 / 模板绑定？

- **一句话**：`(Object->*Func)()` 语法；`GET_FUNCTION_NAME_CHECKED` 编译期函数名检查；UE 的 BindAction/模板绑定全这套（03 篇 BindAbilityActions）。

## E7. USTRUCT 的 operator== 与 AddUnique？

- **一句话**：为容器去重定制 `==`（FSavedAbility 按 Tag、FSaveActor 按名字，09 篇）；**注意**：`for (auto& X : Array)` 修改时小心，`TArray::Remove` 按值（用 == 比较）。

## E8. GC 与智能指针？

- **一句话**：UObject 成员指针必须 UPROPERTY 或 TWeakObjectPtr/TObjectPtr；非 UObject 用 TSharedPtr/TSharedRef（Context 的 DamageType 用 TSharedPtr，与引擎对齐）；接口委托绑组件用 AddWeakLambda 防悬垂（06 篇）。

# F. 表现层（★★★☆☆）

## F1. 描边高亮怎么做？

- **一句话**：`SetRenderCustomDepth(true)` + CustomDepthStencilValue（250 红/251 蓝/252 黄褐，01 篇宏）+ 后处理材质读 CustomStencil → 悬停系统每帧对比 lastActor/thisActor 成对开关（03/11 篇）。**MarkRenderStateDirty** 别忘。

## F2. 死亡表现流水线？

- **一句话**：`Die(DeathImpulse)` → 武器 Detach（KeepWorld，复制）→ NetMulticast Reliable：布娃娃化（SimulatePhysics+PhysicsOnly+重力+AddImpulse，武器 0.1 缩放 bVelChange）→ 胶囊关碰撞 → 溶解（MID+蓝图时间轴）→ 关 Debuff 特效 → 广播 OnDeathDelegate（02 篇）。

## F3. GameplayCue 什么时候用、Replicated 与 Non-Replicated 怎么选？

- **一句话**：Tag 触发的表现事件（统一管理/参数化）；**每端都会本地触发的表现用 Non-Replicated**（火球爆炸——各端 OnHit 本地播，省带宽防双份，12 篇）；服务器单点触发全端表现用 Replicated。

## F4. 异步任务/节点怎么正确清理？

- **一句话**：注册了多少解绑多少（对称）+ `SetReadyToDestroy` + `MarkAsGarbage`（WaitCooldownChange::EndTask，06 篇）；UI 关闭时对每个监听 EndTask。

# G. 性能与工程化（★★★☆☆，展示思考深度）

1. **Tick 纪律**：默认关 Tick，需要时开（EffectActor 动画/弹丸让渡给 MovementComponent）——11/12 篇。
2. **网络带宽**：Context 位掩码序列化（有值才传）→ 01；敌人 Minimal 复制 → 02；Non-Replicated Cue → 12。
3. **静默 bug 防线**：REPNOTIFY_Always / GAMEPLAYATTRIBUTE_REPNOTIFY / MarkAbilitySpecDirty / GAMEPLAYATTRIBUTE_REPNOTIFY——GAS 四大"忘了就静默失效"，主动说出的加分。
4. **防御分层**：配置错误 checkf 炸在开发期（HUD 类/曲线表）；运行期合法缺失降级+日志（缺职业回退 Warrior/缺 Message 行跳过）；哨兵值设计（SetByCaller 的 -1 vs 0 语义）。
