# 00 · 学习路线总览 —— 用「Dura」项目打通 UE5 客户端开发

> **项目一句话**：Dura 是一个 UE5.5+ 的俯视角动作 RPG（Diablo 式操作），**完整实现了 GAS（Gameplay Ability System）**：属性系统、技能系统、伤害计算、Debuff、网络同步、AI、存档、UI 数据绑定全套。它是面试 UE 客户端（尤其是做战斗的项目组）时**最有说服力的项目语言**——因为 GAS 正是大型 ARPG/MMO 的主流技术选型。

## 二、这个项目里值钱的「设计链路」地图

读每篇文档前，先在大脑里挂上这张全景图（各篇展开细节）：

```
【启动地基】01
  模块加载 → AssetManager.StartInitialLoading → 注册 90+ 原生 Tag
  → AbilitySystemGlobals 替换 Context 分配（自定义数据进 GAS 管线的前提）

【数据中枢】02 + 04 + 07
  GameMode 持全局 DataAsset（职业表/技能表/掉落表）
  玩家 ASC 在 PlayerState（Mixed 复制），敌人 ASC 在自身（Minimal 复制）
  属性：Primary(GE) → Secondary(MMC 派生) → Vital(引用上限)——顺序即依赖
  结算：一切伤害写元属性 IncomingDamage → PostGameplayEffectExecute 统一漏斗

【操作与技能】03 + 06
  EnhancedInput → InputTag（解耦键位与技能）→ ASC 遍历 Spec 认领 → TryActivate
  技能内：TargetDataUnderMouse（鼠标目标的网络同步）→ SpawnActorDeferred 生成投射物
  冷却：WaitCooldownChange 双监听（GE 添加→剩余秒数 / Tag 归零→结束）

【伤害管线】05
  FDamageEffectParams（蓝图参数包）→ Library.ApplyDamageEffect
  → SetByCaller 注入数值 / Context 注入机制数据（暴击/击退/Debuff）
  → ExecCalc_Damage：抗性→径向→格挡→护甲→暴击 五段公式 → 输出 IncomingDamage

【表现与网络】12 + 01 + 04
  弹丸：服务器判定 + 客户端预测表现 + Destroyed 兜底
  Context 的 NetSerialize 位掩码（有值才传）保证暴击/格挡数字跨机正确
  属性 REPNOTIFY_Always + OnRep 宏保证客户端 UI 永不失灵

【UI 双范式】08 + 09
  MVC：WidgetController（订阅游戏委托 → 广播蓝图委托）——事件流复杂场景
  MVVM：FieldNotify（属性自动通知 → 蓝图绑定）——表单场景（存档槽位）

【世界与 AI】10 + 11
  接口体系：Combat/Player/Enemy/Highlight/Save 五接口按"身份"组合
  行为树：黑板是 C++ 与 AI 的共享内存；索敌 Service 每帧写黑板
  检查点继承 PlayerStart：激活处=复活处；SaveInterface+SaveGame 属性=世界状态
```

## 三、学这个项目的正确姿势

### 3.1 三层阅读法

1. **链路层**：先读每篇开头的"逻辑链路一句话概括"+ 总图，**能口述数据怎么流**再往下。
2. **函数层**：对照文档精读源码，重点看**每个参数的来源与去向**（文档已逐参数标注）。
3. **重构层**：文档里标了「⚠️ 隐患」「批判点」「项目改造点」的位置（如 SerializeBits 位数、FindCurve 判空、SpawnParams 未传），自己动手修一遍——**能找出别人代码的问题 = 面试加分项**。

### 3.2 必须亲手做过的 5 个 PIE 实验

- 双窗网络模式（ListenServer + Client）观察：属性复制、TargetData 流向、弹丸 Destroyed 兜底（对应 04/06/12 篇）。
- 把 ASC 复制模式 Mixed/Minimal 互换看流量差异（02 篇）。
- 注释掉 `GAMEPLAYATTRIBUTE_REPNOTIFY` 或 `MarkAbilitySpecDirty` 体验"静默 bug"（04/06 篇）。
- 循环里捕获引用的崩溃/错乱（03/08 篇）。
- 新增一个 Tag/技能/掉落物全程不改 C++（01/07 篇）。

### 3.3 与库洛面试的对齐（重要）

库洛（Kuro Games，鸣潮）的客户端岗位 JD 关键词通常覆盖：**UE 引擎原理、C++、战斗/技能系统、动作与手感、UI 框架、网络同步、性能优化**。本项目对口的复习重点：

| 库洛考点方向 | 本项目对应 | 必读篇 |
|---|---|---|
| GAS/技能系统设计 | 全套 GAS 实战（Tag/GE/ExecCalc/Task） | 01/04/05/06 |
| 战斗手感与反馈 | 命中表现（HitReact/受击/击退/死亡冲量）、Cue | 04/06/12 |
| 网络同步 | ASC 复制模式、预测键、TargetData、RepNotify | 02/04/06/12 |
| UI 框架 | MVC 与 MVVM 双范式、FieldNotify | 08/09 |
| 数据驱动 | Tag 体系 + DataAsset 表格 + CurveTable | 01/07 |
| AI/开放世界 | 行为树/黑板、世界状态存档 | 10/11/09 |
| C++ 基础追问 | 文档中所有「语言点」标注（委托/宏/模板/移动语义/容器陷阱） | 全篇散布 |

## 四、GAS 核心概念速成（读 01~06 前的预备课）

| 概念 | 一句话 | 在本项目中的化身 |
|---|---|---|
| **GameplayTag** | 层级化标签，系统的"通用语" | 第 1 篇：90+ 原生 Tag（输入/伤害/状态/冷却） |
| **ASC**（AbilitySystemComponent） | 技能与效果的总管家 | 玩家在 PlayerState、敌人在自身（第 2 篇） |
| **AttributeSet** | 数值集合（Base+Current 双值） | 28 个属性 + 元属性信箱（第 4 篇） |
| **GameplayEffect（GE）** | 修改属性的"效果"（瞬时/持续/无限） | 初始化三连/伤害 GE/冷却 GE/Debuff（04/06） |
| **GameplayAbility（GA）** | 一个技能的完整生命周期 | FireBolt/Electrocute/被动技能（第 6 篇） |
| **AbilityTask** | 技能内的异步操作 | TargetDataUnderMouse 等鼠标点（第 6 篇） |
| **ExecCalc** | 自定义伤害公式执行器 | ExecCalc_Damage 五段公式（第 5 篇） |
| **MMC** | 修改量计算器（属性派生） | MaxHealth = 80+2.5×Vigor+10×Level（第 4 篇） |
| **SetByCaller** | 运行时按 Tag 注入数值 | 伤害/Debuff 四参数注入（第 5 篇） |
| **GameplayCue** | Tag 触发的表现事件 | FireBlast 爆炸（第 12 篇） |
| **GameplayEvent** | 带 Payload 的瞬时消息 | 杀死敌人→XP 事件（第 4 篇） |
| **Prediction Key** | 客户端预测的回执凭据 | 输入路由/TargetData（第 6 篇） |

**学习心法**：GAS 的一切复杂度都可以归结为一个问题——**"数值和状态怎么流动、谁有权修改、怎么让所有机器与 UI 同步知道"**。每读一个文件都问自己这三个问题。
