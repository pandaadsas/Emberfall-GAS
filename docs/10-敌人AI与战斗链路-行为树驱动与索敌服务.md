# 10 · 敌人 AI 与战斗链路 —— 行为树驱动、索敌服务与刷怪系统

> **逻辑链路一句话概括**：
> `玩家走进刷怪区域（SpawnVolume 盒体重叠）` → `触发所有 SpawnPoint 延迟生成敌人（等级/职业在点上配好）` → `敌人 PossessedBy 启动行为树（第 2 篇）` → `BTService_FindNearestPlayer 每帧把"最近活着的玩家+距离"写进黑板` → `行为树按黑板分支（Dead/HitReacting/Stunned/RangedAttacker/TargetToFollow）决策` → `攻击任务（蓝图）让敌人面向目标、播攻击蒙太奇、激活 GA_MeleeAttack 打伤害`。
> **本篇的主旨：AI 是"黑板数据 + 行为树分支"的消费者；战斗能力与玩家共用同一套 GAS。**

# 一、DuraEnemySpawnPoint —— 出生点（★★★★☆）

```cpp
UCLASS()
class DURA_API ADuraEnemySpawnPoint : public ATargetPoint
{
public:
    UFUNCTION(BlueprintCallable)
    void SpawnEnemy();

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Enemy Class")
    TSubclassOf<ADuraEnemy> EnemyClass;

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Enemy Class")
    int32 EnemyLevel = 1;

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Enemy Class")
    ECharacterClass CharacterClass = ECharacterClass::Warrior;
};

void ADuraEnemySpawnPoint::SpawnEnemy()
{
    FActorSpawnParameters SpawnParams;
    SpawnParams.SpawnCollisionHandlingOverride = ESpawnActorCollisionHandlingMethod::AdjustIfPossibleButAlwaysSpawn;

    if(!IsValid(EnemyClass))return;

    if(ADuraEnemy* Enemy = GetWorld()->SpawnActorDeferred<ADuraEnemy>(EnemyClass, GetActorTransform()))
    {
        Enemy->SetLevel(EnemyLevel);
        Enemy->SetCharacterClass(CharacterClass);
        Enemy->FinishSpawning(GetActorTransform());
        Enemy->SpawnDefaultController();
    }
}
```

- **继承 `ATargetPoint`**：TargetPoint 是引擎"关卡里摆着标记位置用的轻量 Actor"——**出生点天然只当位置标记**（无渲染、无碰撞、小图标）。
- **三个配置**：敌人类/等级/职业——**关卡设计师决定"这里刷几级的什么怪"**，与第 7 篇职业表打通（等级→属性 MMC、职业→技能表）。
- **`SpawnParams.SpawnCollisionHandlingOverride = AdjustIfPossibleButAlwaysSpawn`**：出生点被挡时**微调位置但仍生成**（对比第 6 篇投射物的 AlwaysSpawn——弹丸无所谓位置微调，敌人要站在可站位处）。
- **Deferred 五步**（与第 6 篇投射物同款、多一步）：
  1. `SpawnActorDeferred` 半成品；
  2. `SetLevel(EnemyLevel)`——**Set 而非 Init**：BeginPlay 之前写入成员（BeginPlay 里 InitAbilityActorInfo→InitializeDefaultAttributes 读 Level 算属性——**参数必须在 BeginPlay 前就位**，Deferred 的存在意义）；
  3. `SetCharacterClass(...)`——职业同样；
  4. `FinishSpawning` 补完生命周期（BeginPlay 跑、ASC 初始化、属性按等级/职业生成）；
  5. **`SpawnDefaultController()`**：生成默认 AIController——**手动调用**，因为 Deferred 生成不会自动带 Controller（正常 SpawnActor 对 Pawn 会自动 spawn controller，Deferred 模式要显式补）。
- **`SpawnDefaultController` → PossessedBy**（第 2 篇）→ 行为树启动——**出生点代码直接触发 AI 链**。
- **SpawnParams 为什么建了却没传入 SpawnActorDeferred**：调用没带 SpawnParams 参数！**这是代码瑕疵**——意图配置了 AdjustIfPossibleButAlwaysSpawn 但实际没生效（SpawnActorDeferred 的碰撞处理参数未传，用默认值）。学习时的审查发现点：**配置了参数记得真的传进去**。

# 二、DuraEnemySpawnVolume —— 刷怪触发区（★★★★☆）

## 2.1 碰撞配置

```cpp
ADuraEnemySpawnVolume::ADuraEnemySpawnVolume()
{
    PrimaryActorTick.bCanEverTick = false;

    Box = CreateDefaultSubobject<UBoxComponent>("Box");
    SetRootComponent(Box);

    Box->SetCollisionEnabled(ECollisionEnabled::QueryOnly);
    Box->SetCollisionObjectType(ECC_WorldStatic);
    Box->SetCollisionResponseToAllChannels(ECR_Ignore);
    Box->SetCollisionResponseToChannel(ECC_Pawn, ECR_Overlap);
}
```

- **`QueryOnly`**：只做查询（重叠检测）不做物理——纯触发器配置。
- **`ObjectType=ECC_WorldStatic` + 全 Ignore 只对 Pawn Overlap**：**白名单式触发器**——只有角色走进来才触发，弹丸/掉落物穿过不触发。**触发器配置三件套**（Enabled=QueryOnly、ObjectType 归类、ResponseToChannel 白名单）是 UE 碰撞的标准问答题。

## 2.2 触发与自毁

```cpp
void ADuraEnemySpawnVolume::OnBoxOverlap(...)
{
    if(!OtherActor->Implements<UPlayerInterface>())
    {
        return;
    }

    bReached = true;
    for (ADuraEnemySpawnPoint* Point : SpawnPoints)
    {
        if(IsValid(Point))
        {
            Point->SpawnEnemy();
        }
    }
    Box->SetCollisionEnabled(ECollisionEnabled::NoCollision);   // 一次性触发
}

void ADuraEnemySpawnVolume::LoadActor_Implementation()
{
    if(bReached)
    {
        Destroy();
    }
}

bool ADuraEnemySpawnVolume::ShouldLoadTransform_Implementation()
{
    return true;
}
```

- **触发条件**：只认实现了 **IPlayerInterface** 的 Actor（玩家）——敌人穿过去不触发（敌人巡逻路过不会引爆其他区域）。
- **一次性触发**：玩家进入 → 刷完怪 → `NoCollision` 关触发——**同一区域不会因走位反复刷怪**。
- **SaveGame 参与（第 2 篇世界状态的实战样本）**：
  - `bReached` 是 **`UPROPERTY(BlueprintReadOnly, SaveGame)`**——**SaveGame specifier 在此**！SaveWorldState 序列化时 `ArIsSaveGame=true` 的 Archive 只会收它；
  - `LoadActor_Implementation`：读档时若"已被触发过"→ `Destroy()` 自己——**存档里标记为已清的区域不再存在**（重进地图不会重新刷）；
  - `ShouldLoadTransform` 返回 true——恢复位置（编辑器摆哪就是哪）。
- **完整闭环**：`OnBoxOverlap 置 bReached → SaveWorldState 写入 Bytes → LoadWorldState 反序列化 → Execute_LoadActor → Destroy`——**触发式 Actor 的存档复活节彩蛋**，把第 2 篇的世界状态系统落到了实处。

# 三、DuraAIController —— AI 大脑的壳（★★★☆☆）

```cpp
ADuraAIController::ADuraAIController()
{
    BehaviorTreeComponent = CreateDefaultSubobject<UBehaviorTreeComponent>("BehaviorTreeComponent");
    check(BehaviorTreeComponent);

    BlackboardComponent = CreateDefaultSubobject<UBlackboardComponent>("BlackboardComponent");
    check(BlackboardComponent);	
}
```

- **显式创建两组件**：现代 AAIController 其实内建了这两个组件（引擎会自动创建），显式创建是**老教程风格**（课程兼容）——功能等价，但显式引用便于 C++ 侧访问。**面试可提**：新项目可直接用 `GetBlackboardComponent()`/内建组件。
- **C++ 侧没有其他逻辑**：行为树资产、黑板键、决策全在行为树资产（蓝图形态）。**AIController 只当"载体"**。
- **使用处回顾（第 2 篇）**：`DuraEnemy::PossessedBy` 里 Cast 到本类 → `InitializeBlackboard(*BehaviorTree->BlackboardAsset)` → `RunBehaviorTree(BehaviorTree)` → 写入 `HitReacting`/`RangedAttacker` 初始键。

## 3.1 黑板键清单（行为树的"变量表"）

| 键 | 类型 | 写入者 | 消费者 |
|---|---|---|---|
| `TargetToFollow` | Object | BTService_FindNearestPlayer | 攻击任务/移动分支 |
| `DistanceToTarget` | Float | 同上 | 攻击距离判断 |
| `HitReacting` | Bool | DuraEnemy::HitReactTagChanged | 受击时中断当前分支 |
| `Stunned` | Bool | DuraEnemy::StunTagChanged | 眩晕分支 |
| `Dead` | Bool | DuraEnemy::Die | 全树停机 |
| `RangedAttacker` | Bool | DuraEnemy::PossessedBy | 近战/远程分支选择 |

- **黑板是"AI 的共享内存"**——C++ 侧（受击/眩晕/死亡）与行为树侧（服务/任务/装饰器）通过键名通信，**互不 include**。

# 四、BTService_FindNearestPlayer —— 索敌服务 ★★★★★

## 4.1 Service 的身份

```cpp
UCLASS()
class DURA_API UBTService_FindNearestPlayer : public UBTService_BlueprintBase
{
protected:
    virtual void TickNode(UBehaviorTreeComponent& OwnerComp, uint8* NodeMemory, float DeltaSeconds) override;

    UPROPERTY(BlueprintReadOnly, EditAnywhere)
    FBlackboardKeySelector TargetToFollowSelector;

    UPROPERTY(BlueprintReadOnly, EditAnywhere)
    FBlackboardKeySelector DistanceToTargetSelector;
};
```

- **Service vs Task（AI 基础概念）**：**Task 干活**（执行动作返回成功/失败）；**Service 伺候**（挂在节点上按间隔 Tick，不阻塞树，只维护数据）。索敌是典型 Service。
- **`UBTService_BlueprintBase` / `BTTask_BlueprintBase`**：**蓝图基类**——C++ 继承它意味着**蓝图可以继承再覆写 ReceiveTick 等**（本项目 C++ 直接覆写 TickNode，蓝图基类提供 AIOwner/AIOwner->GetPawn() 等便捷访问）。继承 BlueprintBase 而非原生 BTServiceNode 的原因：蓝图子类可覆盖（可扩展性）。
- **`FBlackboardKeySelector`**：**黑板键选择器**——编辑器里下拉选择"写到黑板哪个键"（**键是资产配置不是硬编码**），运行时解析成黑板键 ID。两个选择器=本服务写两个键。

## 4.2 TickNode 精讲

```cpp
void UBTService_FindNearestPlayer::TickNode(UBehaviorTreeComponent& OwnerComp, uint8* NodeMemory, float DeltaSeconds)
{
    Super::TickNode(OwnerComp, NodeMemory, DeltaSeconds);

    // Pawn 已销毁但 Service 仍可能被 Tick，直接保持黑板旧值
    APawn* OwningPawn = AIOwner ? AIOwner->GetPawn() : nullptr;
    if(!OwningPawn) return;

    const FName TargetTag = OwningPawn->ActorHasTag(FName("Player")) ? FName("Enemy") : FName("Player");

    TArray<AActor*> ActorsWithTag;
    UGameplayStatics::GetAllActorsWithTag(OwningPawn, TargetTag, ActorsWithTag);

    float ClosestDistance = TNumericLimits<float>::Max();
    AActor* ClosestActor = nullptr;
    for (AActor* Actor : ActorsWithTag)
    {
        if (IsValid(Actor) && IsValid(OwningPawn))
        {
            if(ICombatInterface* Combat = Cast<ICombatInterface>(Actor))
            {
                if(ICombatInterface::Execute_IsDead(Actor)) continue;    // 尸体不追
            }

            const float Distance = OwningPawn->GetDistanceTo(Actor);
            if (Distance < ClosestDistance)
            {
                ClosestDistance = Distance;
                ClosestActor = Actor;
            }
        }
    }

    UBTFunctionLibrary::SetBlackboardValueAsObject(this, TargetToFollowSelector, ClosestActor);
    UBTFunctionLibrary::SetBlackboardValueAsFloat(this, DistanceToTargetSelector, ClosestDistance);
}
```

- **`AIOwner`（BlueprintBase 的便利成员）**：本服务的 AIController。**Pawn 判空**：注释点明"Pawn 已销毁但 Service 仍可能被 Tick"——行为树组件的销毁与 Pawn 销毁不同步（跨帧间隙），**保黑板旧值**比写空更安全（避免树在一帧内拿到空目标而炸）。
- **反向 Tag 搜索（★ 精妙处）**：`OwningPawn 是 Player？搜 Enemy : 搜 Player`——**这个服务是通用的**：挂在敌人身上搜最近的玩家；若挂在玩家 AI（理论上）也能搜最近的敌人。**用 ActorTag（第 5 篇 IsNotFriend 同款 "Player"/"Enemy"）做阵营查询**。
- **`GetAllActorsWithTag`**：遍历世界中所有该 Tag Actor（O(N)，N=场上该阵营单位数）。**性能账本**：Service 默认每 0.5 秒 Tick 一次（节点 Interval 配置），敌人×玩家小规模无压力；大规模战斗要换"索敌管理器"（PerceptionSystem/分帧）。面试的 AI 优化话题点。
- **死亡过滤**：`IsDead → continue`——**追活人**。没用 IsAlive 的敌人也进距离计算？——实现了 CombatInterface 的才查死亡，没实现的（理论上不该有）照常参与。**防御性宽松**。
- **`TNumericLimits<float>::Max()`**：初值"无穷大"——任何有效距离都更小。**找最近的标准初始化模式**（与第 5 篇 GetClosestTargets 的 `TNumericLimits<double>::Max()` 同款）。
- **`UBTFunctionLibrary::SetBlackboardValueAsObject(this, Selector, Value)`**：写黑板的标准 API（第一参 Owner 供定位 BB 组件，第二参选择器定位键）。**Object 键存 Actor 引用**（黑板内部是弱引用语义？黑板 Object 存的是强引用指针但由 BB 管理——值语义按需）。
- **黑板没找到最近者时**：ClosestActor=nullptr 也照写——**黑板收到 null** → 行为树分支（如"有效目标才攻击"）自然失效。**空值也是有效数据流**。

# 五、BTTask_Attack 与敌人攻击循环（★★★☆☆）

## 5.1 C++ 侧：空壳任务

```cpp
EBTNodeResult::Type UBTTask_Attack::ExecuteTask(UBehaviorTreeComponent& OwnerComp, uint8* NodeMemory)
{
    return Super::ExecuteTask(OwnerComp, NodeMemory);
}
```

- **C++ 只有壳**——`UBTTask_BlueprintBase` 的 **Super::ExecuteTask 会路由到蓝图的 `ReceiveExecute`**（BlueprintBase 的机制：C++ 执行入口转发蓝图事件）。攻击逻辑在蓝图子类（BTTask_Attack 蓝图）：
  - 蓝图大致流程：取黑板 TargetToFollow → 敌人面向目标（ControlRotation/UpdateFacingTarget）→ 播随机攻击蒙太奇（`GetAttackMontages` + `GetRandomTaggedMontageFromArray`，第 6 篇）→ 动画 Notify 触发 GA_MeleeAttack（`TryActivateAbilitiesByTag(Abilities.Attack)`）→ `FinishExecute(true)` 返回任务完成。
- **为什么攻击逻辑放蓝图**：演出节奏（面向目标方式/动画选择）是行为设计，策划在蓝图里调；C++ 提供的都是"素材查询"（蒙太奇数组/插槽位置）。**技能伤害仍走 GAS**（GA_MeleeAttack → CauseDamage/Params 管线）——**AI 与玩家共用伤害管线**，AI 只是"另一个技能施放者"。

## 5.2 完整战斗循环图

```
SpawnVolume 触发（SaveGame 参与）
   └─ SpawnPoint::SpawnEnemy（Deferred：SetLevel/SetClass → FinishSpawning → SpawnDefaultController）
        └─ DuraEnemy::PossessedBy（第 2 篇）
             ├─ 黑板初始化 + RunBehaviorTree
             └─ 初始键：HitReacting=false, RangedAttacker=(职业≠Warrior)
行为树循环（服务器，每帧/服务间隔）
   ├─ [Service] FindNearestPlayer → 黑板 TargetToFollow/DistanceToTarget
   ├─ [Selector 分支优先级]
   │    ├─ Dead=true → 无操作（等 LifeSpan 销毁）
   │    ├─ Stunned/HitReacting → 无操作（硬直）
   │    ├─ RangedAttacker → 保持距离 + 远程攻击 GA（Electrocute/弹道）
   │    └─ 近战 → MoveTo(TargetToFollow) → 距离够 → [Task] Attack
   └─ [Task] Attack（蓝图）
        ├─ 面向目标 + 随机蒙太奇（Montage.Attack.1~4 Tag）
        ├─ 蒙太奇 Notify → TryActivateAbilitiesByTag(Abilities.Attack)
        └─ GA_MeleeAttack（蓝图）→ MakeDamageEffectParams → ApplyDamageEffect（第 5 篇）
受击反馈（第 2 篇）
   └─ AttributeSet 结算 → HitReact Tag → HitReactTagChanged → 黑板 HitReacting=true → 中断攻击
死亡（第 2 篇）
   └─ Die → 黑板 Dead=true → SpawnLoot → 基类 Multicast 表现 → LifeSpan 销毁
```

- **面试考点**：
  1. **Service 与 Task 的区别、TickNode 的间隔控制**；
  2. **黑板键如何被 C++ 与行为树双方读写**（选择器/键名）；
  3. **AI 伤害为什么与玩家走同一 GAS 管线**（可复用抗性/暴击/Debuff 全套）；
  4. **每帧 GetAllActorsWithTag 的性能优化思路**（Perception 组件/分帧/空间索引）。

# 六、动手实验建议

1. 在 SpawnPoint::SpawnEnemy 里把 `SpawnParams` 真的传给 SpawnActorDeferred（`GetWorld()->SpawnActorDeferred<ADuraEnemy>(EnemyClass, GetActorTransform(), nullptr, nullptr, ESpawnActorCollisionHandlingMethod::AdjustIfPossibleButAlwaysSpawn)`），在出生点被墙体堵住时对比两种行为的生成结果。
2. 把 Service 的死亡过滤删掉，观察敌人会攻击尸体（移动到尸体旁反复挥爪）——理解"数据源过滤 vs 行为分支过滤"的两层防御。
3. 在 `OnBoxOverlap` 打日志验证 NoCollision 后不再触发；然后读档（SaveWorldState/LoadWorldState）确认 bReached=true 的 Volume 被销毁。
