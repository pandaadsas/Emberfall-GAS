# 05 - 编译调试与测试记录

> 「制作过程」第 5 篇：从第一行代码到"成熟工具"之间实际发生的事。全部编译错误、三例误报的排查过程、测试方法。**这一篇最有价值——真实的坑比成功的路径更有参考意义。**

---

## 1. 编译错误修复记录（按时间顺序）

### 第一轮：4 个基础错误

| 错误 | 原因 | 修法 |
|---|---|---|
| `SlateOpt.h 找不到` | 这是引擎模块专用的头，游戏模块没有 | 直接删掉 include |
| `Curves/CurveTable.h 找不到` | 5.8 里 UCurveTable 的头是 `Engine/CurveTable.h` | 改 include 路径 |
| `SComboBox` 模板报错一长串 | 5.8 的 SComboBox 要求选项类型是"可空指针类型"，`SComboBox<FString>` 非法 | 改成标准写法 `SComboBox<TSharedPtr<FString>>` |
| `FOnNomadTabSpawnered 不是类` | 5.8 里委托类型改名为 `FOnSpawnTab` | 对着 `TabManager.h` 引擎源码改名 |

### 第二轮：5.8 API 变更集中营

这一轮的特点是**每个错误都指向引擎深处的头文件**，说明是版本 API 变了。逐个去 `D:\UE\UE_5.8\Engine\...` 里翻源码确认：

| 错误 | 5.8 的真实情况 | 修法 |
|---|---|---|
| `CurveTable/RowName 不是 FScalableFloat 的成员` | FScalableFloat 改用 `FCurveTableRowHandle Curve` | 改用 `Curve.IsNull()` / `Curve.GetCurve()` |
| `GetChecked 不是 FAssetRegistryModule 的成员` | 只剩 `Get()` | `.Get()` |
| `IContentBrowserSingleton 未定义类型` | `ContentBrowserModule.h` 只前置声明 | 额外 include `IContentBrowserSingleton.h` |
| `InitToolBarButton 无法从 FSlateBrush* 转换` | 图标参数变成 `TAttribute<FSlateIcon>` | 传 `FSlateIcon(FAppStyle::GetAppStyleSetName(), "ClassIcon.DataAsset")` |
| `GetDurationPolicy 不是 UGameplayEffect 的成员` | 成员 `DurationPolicy` 是 public | 直接用成员 |
| `NoDuration 未声明` | 枚举值改名：`NoDuration` → `Instant` | 改枚举 |
| `ExecClass 不是 FGameplayEffectExecutionDefinition 的成员` | 成员改名 `CalculationClass` | 改名 |
| `CooldownGameplayEffectClass 是 protected` | 引擎成员本来就是 protected（老版本教程代码能在类内访问） | 改用 public 接口 `GetCooldownGameplayEffect()` / `GetCostGameplayEffect()` |
| `UDuraDamageGameplayAbility::Damage 是 protected` | 项目类的 protected UPROPERTY | 反射读取（见 03 篇） |

> **方法论**：编译错误指向引擎头文件时，别猜，直接开引擎源码搜函数/成员名。UE 源码就在本地（`D:\UE\UE_5.8\Engine\Source` 和 `Engine\Plugins\Runtime\GameplayAbilities\Source`），版本完全对应你的开发环境。

### 第三轮：C++ 语言层面的坑

| 错误 | 原因 | 修法 |
|---|---|---|
| `AssetData.IsValid() 左边必须有类` | `const FAssetData AssetData(FSoftObjectPath(...))` 触发 C++ "最令人困惑的解析"（被当成了函数声明） | 改用 AssetRegistry 按包名查询，顺手绕开了 5.8 没有 FSoftObjectPath 构造函数的问题 |
| `Subsystem 声明隐藏了上一个本地声明`（C4456） | if 初始化语句和外层同名变量 | 重构变量作用域 |
| `LNK2019 无法解析 UEditorSubsystem 符号` | Build.cs 忘了依赖 `EditorSubsystem` 模块 | Build.cs 加依赖 |

**经验总结**：9 处编译错误里没有一个是"逻辑写错"，全部是 **API 版本差异 + 模块依赖缺失**。编辑器扩展开发的一半工作量是和引擎版本对齐。

## 2. 运行时 Bug：Ticker 无限重复

第一版 `-ExecCmds` 延迟扫描的 Ticker 回调写成了：

```cpp
FTSTicker::GetCoreTicker().AddTicker(FTickerDelegate::CreateLambda([...](float DeltaTime)
{
    LogValidationReport();
    return true;   // ← BUG：返回 true 表示"继续订阅"，每 15 秒再跑一次！
}), 15.f);
```

结果日志里同一场扫描跑了 4 遍。FTicker 的约定是**返回 false 才会注销**。修正为扫描一次后返回 false。

这类"忘注销的回调"在 UE 里非常常见（Timer/Delegate 同理），日志重复输出是最明显的症状。

## 3. 误报治理（本篇核心）

**一个校验工具的生命线是误报率。** 用户被误报骗三次，第四次就不会再打开这个工具了。我们总共消灭了三类误报：

### 误报 1：`DA.InputTagMissing`（4 条）

- **现象**：DA_AbilityInfo 里 FireBolt/FireBlast/Electrocute/ArcaneShards 四条报"进攻型技能未分配 InputTag，无法装备到快捷栏"。
- **排查**：读 UI 代码发现：
  ```cpp
  // DuraWidgetController.cpp:37
  AbilityInfo.InputTag = UDuraAbilitySystemComponent::GetSlotFromSpec(AbilitySpec);
  ```
  **InputTag 是运行时由技能菜单按装备槽位赋值的**，资产里留空是设计内的正常状态。而且 `FDuraAbilityInfo::InputTag` 的 UPROPERTY 没有 EditDefaultsOnly——它根本不出现在资产编辑器里，本来就不该在资产里有值。
- **修正**：删除该规则，代码里留注释说明原因（防止后人再加回来）。
- **教训**：**一个属性"为空"是否算错误，取决于它是"配置数据"还是"运行时数据"。判断方法：查它的所有写入方。**

### 误报 2：`GE.CostZero`（4 条）

- **现象**：四个 Cost GE 全部报"1 级蓝耗为 0"。
- **排查过程**（完整的三段式）：
  1. 怀疑求值 API（`GetStaticMagnitudeIfPossible`）在 5.8 行为变化 → 换成手工求值 `Value × Curve.Eval(1)`，**还是报**；
  2. 加调试日志打印全部中间量：
     ```
     GE_Cost_FireBolt: Value=-1.0 Row=FireBolt Eval1=2.5 最终=-2.5
     ```
     曲线行存在、行名正确、**值不是 0，是负数**；
  3. 查项目代码：`DuraFireBolt.cpp` 里 `const float ManaCost = FMath::Abs(GetManaCost(Level));` —— 全项目都用 `FMath::Abs` 取绝对值。**这个项目的蓝耗按 GAS 惯例存负数**。
- **修正**：判定条件从 `CostValue <= 0` 改为 `FMath::IsNearlyZero(FMath::Abs(CostValue))`，报错文案补充约定说明。
- **教训**：调试顺序应该是"**打印中间量 → 拿到事实 → 再怀疑 API**"，我一开始直接跳到了第一步怀疑 API，多绕了一圈。

### 误报 3（预防性）：敌人技能的冷却/蓝耗

敌人普攻没有冷却和蓝耗是合理设计。规则里对 `/Enemy/` 目录的资产降级：冷却缺失从"警告"降为"提示"，成本缺失直接不报。**规则强度要区分"玩家技能"和"敌人技能"。**

### 治理结果

```
第一版：  错误 0 | 警告 5 | 提示 11   （含 8 条误报）
最终版：  错误 0 | 警告 1 | 提示 7    （0 误报，全部经人工核对）
```

## 4. 测试方法：为什么用控制台命令而不是点按钮

本次开发环境里自动化鼠标/键盘注入对这个编辑器窗口不可用（合成输入被系统策略拒绝、屏幕动画导致点击帧失效）。因此设计了一套**不依赖 UI 的端到端测试方案**——这也正是给工具加控制台命令的初衷：

```
命令行启动 → 自动执行命令 → 结果落盘 → 脚本/人工核对
```

具体步骤：

1. `tools\Build_DuraEditor.bat` 编译通过（每一轮改动后）；
2. 用 `-ExecCmds="Dura.GASValidatorOpen,Dura.GASValidate"` 启动编辑器：
   - 自动打开校验器面板（验证标签页注册、Slate 渲染）；
   - 延迟 15 秒自动扫描（验证 AssetRegistry 就绪后的完整规则链）；
3. 检查 `Saved/Logs/Dura.log` 里的 `[GAS校验]` 报告（验证扫描数量、错误分布、规则文案）；
4. 检查 `Saved/GASValidator/*.md` 报告文件（验证导出功能）；
5. 用屏幕截图核对面板的实际渲染效果（列表内容、统计行、严重度颜色）。

**因为控制台命令和面板按钮调用的是同一个 `UGasValidatorSubsystem::StartScan()`**，这条路径覆盖了按钮点击的全部逻辑。唯一无法自动验证的是双击行跳转资产（需要真实鼠标双击），该功能用的是 `UAssetEditorSubsystem::OpenEditorForAsset` + `SyncBrowserToAssets` 两个标准引擎 API，风险可控——你醒来后双击任意一行结果即可亲自确认。

## 5. 多轮验证结果对照

| 轮次 | 扫描资产数 | 结果 | 状态 |
|---|---|---|---|
| 第 1 次（首版核心） | 58 | 0 错误 / 5 警告 / 11 提示 | 逻辑跑通，但含 8 条误报 |
| 第 2 次（修 Ticker + 删 InputTag 规则） | 58 | 0 错误 / 5 警告 / 7 提示 | 4 条误报消失，CostZero 仍误报 |
| 第 3 次（调试日志定位负数蓝耗） | 58 | — | 确认根因：项目蓝耗存负数 |
| 第 4 次（修正判定 + 全链路导出） | 58 | 0 错误 / 1 警告 / 7 提示 | **0 误报，报告文件正常生成** |

58 这个数字和 `Content/Blueprints/AbilitySystem` 下的 uasset 文件数完全一致，说明资产枚举没有遗漏。

## 6. 已知边界（诚实清单）

- 扫描范围固定为 `/Game/Blueprints/AbilitySystem`（本项目的 GAS 资产约定位置）；如果以后把 GA 放到别的目录，需要改 `GasScanRootPath`；
- 只扫描"静态配置"，不覆盖运行时行为（比如蓝图事件图表里 ApplyGameplayEffect 用动态类生成的场景）；
- 双击跳转、过滤/搜索框为标准 Slate/引擎 API 实现，未经自动化测试但风险低；
- 每 15 秒延迟扫描是给 `-ExecCmds` 启动场景的兜底，手动在控制台输入命令且注册表已就绪时会立即执行。

这些边界都写进了代码注释，后续扩展见第 10 篇。
