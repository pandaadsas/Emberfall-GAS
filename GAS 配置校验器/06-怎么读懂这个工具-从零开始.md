# 06 - 怎么读懂这个工具：从零开始的地图

> 「原理精讲」第 1 篇。这一篇不写新知识，只做一件事：**给你一张"读代码的地图"**——先看哪个文件、每个文件在讲什么故事、一个请求在代码里怎么流动。读完这篇，你再打开任何一份源码都不会迷路。

---

## 0. 先打个比方

把整个工具想象成一家**医院体检中心**：

| 工具里的东西 | 比方 |
|---|---|
| 「GAS 校验」工具栏按钮 / 控制台命令 | 挂号窗口（两个窗口，挂同一个号） |
| `UGasValidatorSubsystem` | 前台护士站（登记、安排、发结果单） |
| `FGasValidatorCore` | 体检医生（真正做检查的人） |
| 16 条校验规则 | 16 项体检项目 |
| `SGasValidatorPanel` | 报告查询大屏（把结果展示出来，还能点） |
| `FGasValidationIssue` | 一张化验单（哪个器官、什么指标、超标多少） |
| `FGasValidationResult` | 整套体检报告（所有化验单 + 总结） |

**你不需要按代码文件顺序读，跟着"一次体检的流程"读最顺。** 下面就是这条流程。

## 1. 一次扫描的完整生命线（10 个停靠点）

假设你点了一下「开始扫描」按钮。代码会依次经过这些位置（建议对照源码走一遍）：

```
① SGasValidatorPanel::OnScanClicked()                面板.cpp
      "用户点了按钮"
        │
        ▼
② UGasValidatorSubsystem::StartScan()                子系统.cpp
      "把活儿交给护士站"
        │
        ▼
③ FGasValidatorCore::RunValidation()                 核心.cpp
      "医生开始体检"
        ├─ 第0步 收集资产清单   （AssetRegistry 枚举 58 个资产）
        ├─ 第1步 加载并分组     （GA / GE / DA_AbilityInfo / DA_CharacterClassInfo）
        ├─ 第2步 扫描所有 GA    （每条 GA 规则在这里，顺便记交叉引用表）
        ├─ 第3步 扫描数据资产   （DA_AbilityInfo / DA_CharacterClassInfo 规则）
        ├─ 第4步 扫描所有 GE    （交叉引用表在这里派上用场）
        └─ 第5步 反查未登记技能
        │
        ▼
④ 返回 FGasValidationResult                          类型.h 里定义的结构
      "一叠化验单 + 总结页"
        │
        ▼
⑤ UGasValidatorSubsystem 写日志 + 存下 LastResult     子系统.cpp
        │
        ▼
⑥ OnValidationCompleted.Broadcast(LastResult)         子系统.cpp
      "护士站广播：体检结果出来了！"
        │
        ▼
⑦ SGasValidatorPanel::HandleValidationCompleted()     面板.cpp
      "大屏收到广播，刷新显示"
        ├─ 把 Issues 转成列表行数据 FilteredRows
        ├─ UpdateStatsText() 更新统计行
        └─ ListView->RequestListRefresh()
        │
        ▼
⑧ SListView 找每行要 UI → SGasValidatorRow::GenerateWidgetForColumn()
      "每张化验单渲染成表格里的一行"
        │
        ▼
⑨ 你双击某一行 → OnRowDoubleClicked → OpenIssueAsset()
      "点化验单跳到对应科室"（打开资产 + 内容浏览器定位）
        │
        ▼
⑩ 你点「导出报告」→ Subsystem->ExportReport() → Saved/GASValidator/*.md
      "把报告打印带走"
```

**读代码时永远问自己"我现在在生命线的第几个点"，就不会迷路。**

## 2. 六个文件，各自的故事

按"读的顺序"排列，每个文件用一句话 + 关键内容概括：

### ① `GasValidatorTypes.h`（60 行，先读它）

定义"化验单长什么样"。三个东西：

- `EGasValidationSeverity`：严重度枚举（错误/警告/提示）；
- `FGasValidationIssue`：一条问题 = 严重度 + 规则 ID + 类别 + 资产名 + 路径 + 人话说明；
- `FGasValidationResult`：一次扫描 = 问题列表 + 数量统计 + 耗时。

整个工具的数据语言都在这一个头文件里，读懂它你就懂了所有层之间传的是什么。

### ② `GasValidatorCore.h/.cpp`（约 600 行，工具的心脏）

医生本人。`RunValidation()` 一个公开方法，五步流水线（03 篇详讲）。其余全是 private 助手：目录判定、曲线求值、反射读取。

**读它的技巧：不要从上往下读**。先读 `RunValidation()` 的"第 0 步～第 5 步"注释框架，再跳进去读你感兴趣的某一步。

### ③ `GasValidatorSubsystem.h/.cpp`（约 100 行）

护士站。三件事：`StartScan()`（调医生 + 写日志 + 广播）、`GetLastResult()`（存结果）、`ExportReport()`（打印报告）。

它是个 `UEditorSubsystem`——UE 的"编辑器级全局单例"，想知道这是什么看第 9 篇名词卡。

### ④ `SGasValidatorPanel.h/.cpp`（约 400 行）

大屏。`Construct()` 搭界面（按钮/统计/表格），三个回调：扫描点击、导出点击、双击行。加一个过滤刷新逻辑。

### ⑤ `DuraEditor.h/.cpp`（约 130 行）

医院大门和挂号窗口。`StartupModule()` 注册标签页和工具栏按钮，`RegisterMenus()` 挂按钮，三条控制台命令。

### ⑥ `DuraEditor.Build.cs`（30 行）

采购清单。模块依赖声明（02 篇逐条讲过）。

## 3. 三个"贯穿全局"的问题（读代码时自问）

**Q1：这个变量是谁的？**
核心.cpp 里同时出现 `GACDO`（技能的默认对象）、`GECDO`（效果的默认对象）、`Entry`（DA 表的一条）、`AssetData`（磁盘上的资产记录）。搞混了就读不懂。记住对应关系：

```
AssetData（资产在 AssetRegistry 里的"户口"）
    └── GetAsset() → UObject（蓝图对象）
            └── GeneratedClass → UClass（蓝图生成的类，名字带 _C）
                    └── GetDefaultObject() → CDO（你在 Class Defaults 里看到的那些默认值）
```

**Q2：这张表是干嘛的？**
核心.cpp 里有三个 TMap 交叉引用表（`GEUsedAsCooldown/Cost/Damage`），一个 TSet（`RegisteredAbilityPaths`）。它们的存在原因：**GE 自己不知道自己是干嘛的，必须靠"谁在用它"来判定**（03 篇第 2 节）。

**Q3：这个广播/回调是谁发给谁的？**
整个工具只有一条广播链：子系统 `OnValidationCompleted` → 面板 `HandleValidationCompleted`。面板订阅在 `Construct()`、退订在析构函数。看到 `AddRaw/Remove` 就想想这对"订阅-退订"（第 4 篇第 3 节讲过为什么必须成对）。

## 4. 推荐的动手验证路线

光读不练假把式。按这个顺序动手，每步 5 分钟：

1. **跑一次**：编辑器里打开面板（工具栏「GAS 校验」），点扫描，看结果；
2. **改文案**：在 `GasValidatorCore.cpp` 搜 `GA.NoCostGE`，把警告文案改几个字，关编辑器 → `tools\Build_DuraEditor.bat` → 重开编辑器 → 点扫描 → 看到你的改动。**走通"改代码→编译→验证"闭环是学会编辑器开发的分水岭**；
3. **关掉一条规则**：把 `GA.NoCostGE` 那个 `AddIssue` 注释掉，重编译，扫描确认警告少了一条；
4. **加一条规则**：跟着第 10 篇的教程，亲手加一条新校验。

做完这四步，这个工具对你就不再是"别人写的代码"了。

## 5. 名词速查（详细版在第 9 篇）

| 名词 | 一句话 |
|---|---|
| 模块（Module） | UE 代码的组织单元，编译成一个 DLL。分 Runtime/Editor 等类型 |
| CDO | 类默认对象，蓝图 Class Defaults 里那些值真正存放的地方 |
| AssetRegistry | 引擎的"资产户口本"，不打开资产就能查到资产信息 |
| CDO | 见上 |
| 反射（Reflection） | UE 在编译期给每个 UPROPERTY/ UCLASS 生成的"自我描述数据"，运行时可按名字读写字段 |
| Slate | UE 的 UI 框架，编辑器界面全靠它 |
| Subsystem | UE 提供的"全局单例"标准写法，编辑器工具用 UEditorSubsystem |
| Nomad Tab | 不依附于资产/关卡的独立编辑器标签页 |
| ExecCmds | 启动参数，让编辑器开机自动执行控制台命令 |
