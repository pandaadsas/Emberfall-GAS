# 07 - 校验规则逐条精讲

> 「原理精讲」第 2 篇。把 16 条规则**每一条**讲透：它在防什么事故、事故的原理是什么、代码怎么判定、在哪实现。读完这篇你不仅懂工具，还会把 GAS 配置的坑系统地过一遍。
>
> 所有代码都在 `Source/DuraEditor/GasValidatorCore.cpp`，用规则 ID 搜索即可定位。

---

## 第一组：成本与冷却（7 条）

### GA.NoCostGE —— "技能不耗蓝"

**防什么事故**：策划新建了一个火球术，忘了配 Cost GE。玩家可以无限搓火球。

**原理**：GAS 里技能施放会走 `CommitAbility`，它应用 Cost GE 扣蓝。Cost GE 没配 = 扣蓝这步空转 = 免费放技能。

**怎么判**（第 2 步扫 GA 时）：

```cpp
if (const UGameplayEffect* CostGE = GACDO->GetCostGameplayEffect())
{
    GEUsedAsCost.FindOrAdd(CostGE->GetClass()->GetPathName()).Add(AssetData.AssetName.ToString());
}
else if (!bPassive && !bEnemy)   // 只有玩家主动技能才警告
{
    AddIssue(Warning, "GA.NoCostGE", ...);
}
```

注意 `GetCostGameplayEffect()` 是引擎的 public 接口——它内部就是去读 protected 的 `CostGameplayEffectClass` 并返回 CDO。**优先用引擎的公开访问器，读不到再用反射**。

**差异化**：被动技能（光环类）和敌人技能不耗蓝是正常设计，不报。

---

### GA.NoCooldownGE —— "技能没有冷却"

和上一条对称：`CooldownGameplayEffectClass` 没配，技能放完立刻能再放。玩家技能警告、敌人技能降为提示（敌人普攻无冷却很常见）。

---

### GE.CostNoManaModifier —— "配了 Cost GE 但里面没扣蓝"

**防什么事故**：策划配了 Cost GE，但 GE 里面忘了加"修改 Mana 属性"的条目。GE 会成功应用，**但什么都没改**——技能照样免费。

**怎么判**（第 4 步扫 GE，查"谁在用它"的表）：

```cpp
if (CostUsers)   // 有 GA 把这个 GE 当 Cost 用
{
    bool bHasManaModifier = false;
    for (const FGameplayModifierInfo& Mod : GECDO->Modifiers)
    {
        if (Mod.Attribute == UDuraAttributeSet::GetManaAttribute())  // 是不是改 Mana？
        {
            bHasManaModifier = true;
            break;
        }
    }
    if (!bHasManaModifier) AddIssue(Error, "GE.CostNoManaModifier", ...);
}
```

`Mod.Attribute == UDuraAttributeSet::GetManaAttribute()` 是 FGameplayAttribute 的比较——和项目自己的 `GetManaCost()` 里的写法一模一样（见 `DuraGameplayAbility.cpp:22`），**校验器的判定标准与游戏运行时的消费标准保持同源**，这是避免误报的关键习惯。

---

### GE.CostZero —— "蓝耗数值是 0"

**防什么事故**：Cost GE 里有 Mana 修改器，但数值/曲线没配 → 扣了 0 点蓝，还是免费。

**怎么判**：

```cpp
const FScalableFloat* CostFloat = GetScalableFloatFromMagnitude(Mod.ModifierMagnitude);
if (CostFloat) CostValue = EvaluateScalableFloatAtLevel(*CostFloat, 1.f);   // 手工求值（03 篇第 4 节）

// 本项目（GAS 惯例）蓝耗存负数，取绝对值判断是否为 0
if (FMath::IsNearlyZero(FMath::Abs(CostValue))) AddIssue(Warning, "GE.CostZero", ...);
```

**这条规则是整个开发过程中误报最多的一条**（负数蓝耗的排查故事见 05 篇），最终版长这样。

---

### GE.CooldownPolicyWrong —— "冷却瞬间结束"

**原理**：GE 有三种持续时间策略：`Instant`（打一下就完）/ `Infinite`（永不结束）/ `HasDuration`（持续 N 秒）。冷却 GE 必须是 `HasDuration` 且时长 > 0——GAS 移除冷却 GE 的时机就是"持续时间到了"。策略配成 Instant，应用完立刻被移除，冷却形同虚设。

**怎么判**：

```cpp
if (CooldownUsers && GECDO->DurationPolicy != EGameplayEffectDurationType::HasDuration)
    AddIssue(Error, "GE.CooldownPolicyWrong", ...);
```

---

### GE.CooldownDurationZero —— "冷却时长为 0"

策略对了，但 Set Duration 的数值/曲线没配（求出来 0）。和 CostZero 同款求值方法。

---

### GE.CooldownNoGrantedTag —— "技能永久卡死"（最严重的一条）

**防什么事故**：这条值得单独讲透，因为它坏的方式最隐蔽。

这个项目里技能冷却结束的检测机制是（`WaitCooldownChange` 异步任务）：

```
技能释放 → 冷却 GE 被应用 → GE 把自己的 Cooldown Tag（如 Cooldown.Fire.Bolt）授予 ASC
        → 技能被锁定（因为身上有冷却 Tag）
        → 持续时间到 → GE 被移除 → Tag 从 ASC 上消失
        → "TagRemoved" 事件触发 → 异步任务回调 → 技能解锁
```

**整条链的关键是那个 Tag**。如果冷却 GE 忘了在"Granted Tags"里加 Tag：应用 → 锁定 → 到时间 → GE 移除 → **但没有 Tag 移除事件** → 异步任务永远等不到回调 → **技能从此永久锁死，重开存档都救不回来**。

**怎么判**：

```cpp
if (CooldownUsers && GECDO->GetGrantedTags().Num() == 0)
    AddIssue(Error, "GE.CooldownNoGrantedTag", "冷却移除监听（WaitCooldownChange）靠标签恢复技能，缺了它技能会永久卡死…");
```

## 第二组：引用完整性（4 条）

### GA.NoDamageEffectClass —— "打人不掉血"

`UDuraDamageGameplayAbility` 的子类（所有输出技能）必须在蓝图里配 `DamageEffectClass`（就是 GE_Damage）。它是 `CauseDamage()` 的载体——没配，命中逻辑应用了一个空效果，动画全对、音效全对、**就是不掉血**。

这里读取用了反射（成员是 protected）：

```cpp
const UClass* DamageEffectClass = ReadClassProperty(DamageGA, TEXT("DamageEffectClass"));
if (DamageEffectClass == nullptr) AddIssue(Error, "GA.NoDamageEffectClass", ...);
```

### GE.DamageNoExec —— "伤害公式没运行"

**原理**：这个项目的伤害不是 GE 直接改血，而是 GE 触发 `ExecCalc_Damage`（执行计算器）跑完整公式（攻击/防御/暴击/抗性/减益…）。ExecCalc 挂在 GE 的 **Executions** 数组里。伤害 GE 里没有 ExecCalc_Damage = 公式根本不执行。

**怎么判**：

```cpp
for (const FGameplayEffectExecutionDefinition& ExecDef : GECDO->Executions)
{
    if (ExecDef.CalculationClass && ExecDef.CalculationClass->IsChildOf(UExecCalc_Damage::StaticClass()))
    { bHasDamageExec = true; break; }
}
```

### GE.Empty —— "空壳废件"

一个 GE：无持续时间、无修改器、无执行器、不授予标签 → 它应用了等于没应用。多半是配到一半忘了，或废弃没删。

### Asset.LoadFailed —— "资产坏了"

`AssetData.GetAsset()` 返回空 = 文件损坏或内部引用烂了。这种资产在内容浏览器里可能都打不开，工具帮你第一时间发现。

## 第三组：标签一致性（6 条）

### GA.DamageTypeInvalid / GA.DamageTypeNotDamage —— "伤害恒为 0 的标签陷阱"

**原理**（这是 GAS 里最经典的静默失败）：这个项目的伤害数值是通过 **SetByCaller + 伤害类型标签** 传递的：

```
技能释放时：AssignTagSetByCallerMagnitude(伤害Spec, DamageType, 25)   // "25 点火伤"
ExecCalc 里：Spec.GetSetByCallerMagnitude(DamageType标签)             // 按同一个标签取出来
```

**两边必须用同一个标签**。如果技能的 DamageType 拼错（比如写成了非 Damage 系列的标签），赋值和取值各用各的，取出来是默认值 0 → 伤害恒为 0，**没有任何报错**。

**怎么判**：

```cpp
if (DamageType == nullptr || !DamageType->IsValid())
    AddIssue(Error, "GA.DamageTypeInvalid", ...);          // 压根没设
else if (FDuraGameplayTags::Get().Damage.IsValid()
         && !DamageType->MatchesTag(FDuraGameplayTags::Get().Damage))
    AddIssue(Error, "GA.DamageTypeNotDamage", ...);        // 设了，但不是 Damage 家族的
```

`MatchesTag(Damage)` 用了 GameplayTag 的**层级匹配**：`Damage.Fire` 匹配父标签 `Damage`，`Attributes.Primary.Strength` 不匹配。用"家族判定"而不是硬编码四个元素枚举，以后加新伤害类型不用改工具。

### DA.AbilityTagInvalid / DA.AbilityTagDuplicate

技能菜单全靠 AbilityTag 查询 `FindAbilityInfoForTag`。无效标签查不到东西；**重复标签更阴险**——查询永远命中第一条，第二条技能在菜单里是幽灵（显示不出来/学不了）。判定用一个 `TMap<FString,int32>` 记"标签→首次出现的行号"，第二次出现即报错。

### DA.CooldownTagMismatch / DA.CooldownTagMissing

技能菜单显示冷却的原理：监听 `CooldownTag` 的移除。条目里填的 CooldownTag 必须**和冷却 GE 实际授予的 Tag 完全一致**（`HasTagExact`，精确匹配，连层级匹配都不行——监听的就是那一个具体 Tag）。这是 DA、GA、GE **三个资产之间的链式校验**，是整个工具里"跨资产"最深的规则。

## 第四组：数据资产（DA_* / CCI_* 系列）

### DA.EntryMissingAbility / DA.IconMissing / DA.BackgroundMissing / DA.LevelRequirementInvalid

直白的字段检查：技能类配没配、图标/背景材质配没配、等级需求是不是 ≥1。严重度按"对玩家的影响"定级：技能类缺失是错误（功能坏死），图标缺失是警告（显示难看），背景材质是提示（有默认样式兜底）。

### CCI.* 系列（DA_CharacterClassInfo 的 8 项）

角色职业数据资产是**角色出生初始化**的源头（`InitializeDefaultAttributes` 用它给角色套属性 GE）：

| 规则 | 防的事故 |
|---|---|
| `CCI.PrimarySetByCallerMissing` | 读档恢复属性时主属性初始化失败 |
| `CCI.SecondaryMissing` | 护甲/暴击等次级属性全 0 |
| `CCI.SecondaryInfiniteMissing` | 蓝/体力回复不生效 |
| `CCI.VitalMissing` | 血量蓝量不初始化 |
| `CCI.PrimaryAttributesMissing` | 某职业主属性全 0 |
| `CCI.StartupAbilityMissing` | 出生授予技能时遇到空类 |
| `CCI.CommonAbilityMissing` | 所有职业的公共技能出问题 |
| `CCI.DamageCoefficientsMissing` | 伤害系数曲线缺失（警告） |

这组规则没有技术难度，价值在于**把"角色出生就坏"这类最难排查的问题前置到配置阶段**。

### GA.NotRegistered —— "菜单里看不到的技能"

反向检查：扫描完所有数据资产后，把被引用过的 GA 类路径放进 `RegisteredAbilityPaths` 集合；最后遍历所有玩家主动技能，不在集合里的报提示。防的是"写了新技能、忘了在技能菜单登记"。

## 第五组：数值曲线（4 条）

### 为什么曲线行值得单独查

`FScalableFloat` 引用曲线表的方式是"表 + 行名"（比如 CT_SpellCost 的 "FireBolt" 行）。**行名是手敲的字符串**——敲错一个字母，运行时查不到行，数值静默退化为 0。这类错误在编辑器里完全无感。

### GA.DamageCurveRowMissing / GE.ModifierCurveRowMissing / CCI.XPRewardCurveMissing

同一条规则的三个应用点：

```cpp
bool FGasValidatorCore::DoesCurveRowExist(const FScalableFloat& ScalableFloat)
{
    if (ScalableFloat.Curve.IsNull()) return true;   // 没配曲线 = 用常量，合法
    return ScalableFloat.Curve.GetCurve(TEXT("GASValidator"), false) != nullptr;  // 行真的存在吗？
}
```

`GetCurve(bWarnIfNotFound=false)`：第二个参数传 false 是工具的礼貌——**别在输出日志里刷引擎警告**（用户会以为是引擎出问题），发现问题的应该是工具自己的报告。

### GA.DamageZero

伤害基础值 0 且没配曲线 → 提醒"如果这个技能该有伤害，数值还没填"。

## 附：规则与"游戏消费方"对照表

每条规则其实都在模仿"游戏运行时谁会消费这个配置"。这张表是理解全部规则的总钥匙：

| 配置 | 游戏里的消费方（代码位置） | 于是校验器检查 |
|---|---|---|
| Cost GE | `CommitAbility` 扣蓝 | 存在、改 Mana、数值非 0 |
| Cooldown GE | `WaitCooldownChange` 监听 Tag 移除 | HasDuration、时长>0、**授予 Tag** |
| DamageEffectClass | `CauseDamage` → `ApplyDamageEffect` | 存在、挂 ExecCalc_Damage |
| DamageType | ExecCalc 按 Tag 读 SetByCaller | 有效、属于 Damage 家族 |
| AbilityTag | `FindAbilityInfoForTag` 查表 | 有效、不重复 |
| CooldownTag | 技能菜单监听 Tag | 与冷却 GE 授予的 Tag 精确一致 |
| 曲线行 | `FScalableFloat::GetValueAtLevel` | 行存在 |
| DA_CharacterClassInfo | `InitializeDefaultAttributes` 出生初始化 | 8 个引用全部有效 |

**看懂"谁消费 → 消费失败是什么现象"，你就能自己发明新规则**（第 10 篇的教程就是教你走这个流程）。
