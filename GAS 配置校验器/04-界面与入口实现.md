# 04 - 界面与入口实现

> 「制作过程」第 4 篇：Slate 面板、编辑器子系统、控制台命令。以及为什么中途把架构重构成"面板 + 子系统"两层。

---

## 1. Slate 是什么，和 UMG 什么关系

- **UMG**：游戏内 UI（HUD、菜单），Designer 里拖控件，运行时渲染。
- **Slate**：UE 一切 UI 的底层框架，**编辑器自己就是用 Slate 写的**。内容浏览器、Details 面板全是 Slate。

给编辑器做工具界面 = 写 Slate。写法是 C++ 的声明式嵌套：

```cpp
SNew(SVerticalBox)
+ SVerticalBox::Slot().AutoHeight()
[
    SNew(SButton).Text(FText::FromString(TEXT("开始扫描")))
]
+ SVerticalBox::Slot().FillHeight(1.f)
[
    // 列表...
]
```

`[ ]` 里放子控件，`.Slot()` 控制布局参数。看熟了就是"搭积木"。

## 2. 面板布局

`SGasValidatorPanel` 一屏四块：

```
┌──────────────────────────────────────────────────────┐
│ [开始扫描] [导出报告]         [全部▾] [按资产/规则搜索…] │ ← 工具行
│ 扫描 58 个资产 · 错误 0 · 警告 1 · 提示 7 · 耗时 0.39 秒 │ ← 统计行
├──────┬────────┬──────────────┬──────────┬────────────┤
│ 严重度 │ 类别    │ 规则          │ 资产      │ 问题说明    │ ← 表头
│ ●警告 │ 数据资产│ DA.IconMissing│ DA_Ability│ 第 8 条…    │
│ ●提示 │ 成本与…│ GA.NoCooldown…│ GA_HitReact│ 该敌人技能…│
│  …   │        │              │          │            │
└──────┴────────┴──────────────┴──────────┴────────────┘
```

列表用 `SListView` + `SHeaderRow`，每行是自定义的 `SGasValidatorRow`（`SMultiColumnTableRow` 子类，按列名生成对应单元格）。严重度文字带颜色：错误红、警告黄、提示灰。

几个实现细节：

- **数据与视图分离**：SListView 需要一个 `TArray<TSharedPtr<行数据>>`，我们把每条问题包成 `FGasValidationRowItem`（内部持有 `TSharedPtr<FGasValidationIssue>`）。列表刷新只换数组，不动逻辑数据。
- **过滤不重新扫描**：严重度下拉（全部/错误+警告/仅错误）和搜索框只操作 `FilteredRows`（`RebuildFilteredRows()`），原始结果 `LastResult` 永远完整。
- **双击行跳转资产**：

```cpp
void SGasValidatorPanel::OpenIssueAsset(const FGasValidationIssue& Issue) const
{
    // 打开资产编辑器（蓝图类路径带 _C 后缀，OpenEditorForAsset 能直接处理）
    if (UAssetEditorSubsystem* AES = GEditor->GetEditorSubsystem<UAssetEditorSubsystem>())
    {
        AES->OpenEditorForAsset(Issue.ObjectPath);
    }
    // 内容浏览器里定位：把类路径还原成资产路径（去掉结尾 _C）再同步
    FString AssetObjectPath = Issue.ObjectPath;
    AssetObjectPath.RemoveFromEnd(TEXT("_C"));
    TArray<FAssetData> AssetsToSync;
    FModuleManager::LoadModuleChecked<FAssetRegistryModule>("AssetRegistry").Get()
        .GetAssetsByPackageName(FName(*FPackageName::ObjectPathToPackageName(AssetObjectPath)), AssetsToSync);
    if (AssetsToSync.Num() > 0)
    {
        FModuleManager::LoadModuleChecked<FContentBrowserModule>("ContentBrowser").Get()
            .SyncBrowserToAssets(AssetsToSync);
    }
}
```

> **踩坑记录**：UE 5.8 里旧的 `GEditor->SyncBrowserToObjects(FSyncObjectRequest)` 已不存在，要用 `IContentBrowserSingleton::SyncBrowserToAssets(TArray<FAssetData>&)`；且 `FAssetData` 没有 `FSoftObjectPath` 构造函数，得先转包名再查 AssetRegistry。另外 `FContentBrowserModule.h` 只前置声明了 `IContentBrowserSingleton`，要额外 include `IContentBrowserSingleton.h` 才能调方法。

## 3. 为什么中途引入了子系统（一次架构重构）

最初版本里，扫描逻辑直接写在面板的按钮回调里：

```cpp
FReply SGasValidatorPanel::OnScanClicked()
{
    LastResult = FGasValidatorCore::RunValidation();  // 面板自己跑
    ...刷新列表
}
```

问题马上出现了：**我想加一条控制台命令来触发扫描（自动化测试需要），却发现命令根本拿不到面板实例**——面板活在标签页的 Slate 树里，外部没法引用它。

解决方案就是把"扫描能力"从面板里抽出来，放进 **EditorSubsystem**（UE 提供的编辑器级单例，`GEditor->GetEditorSubsystem<T>()` 全局可取）：

```cpp
UCLASS()
class UGasValidatorSubsystem : public UEditorSubsystem
{
    GENERATED_BODY()
public:
    DECLARE_MULTICAST_DELEGATE_OneParam(FOnValidationCompleted, const FGasValidationResult&);

    void StartScan();                       // 任何入口都调它
    const FGasValidationResult& GetLastResult() const;
    FString ExportReport() const;           // 导出 Markdown，返回文件路径

    FOnValidationCompleted OnValidationCompleted;  // 扫描完成广播

private:
    FGasValidationResult LastResult;
};
```

重构后的调用关系：

```
工具栏按钮 ─┐
窗口菜单   ─┤→ 打开面板
控制台命令 ─┘      │
                  ▼
   面板 Construct 时订阅 OnValidationCompleted
                  │
                  ▼
面板按钮「开始扫描」→ Subsystem->StartScan() ─→ FGasValidatorCore::RunValidation()
                  ▲                                        │
                  └───────── 广播结果 ←─────────────────────┘
```

好处立竿见影：

1. **控制台命令和按钮走完全相同的代码路径**——测了一条等于测了两条（我们的自动化测试正是靠这一点完成的）；
2. 结果存在子系统里，**面板关了再开还能显示上一次结果**（Construct 时查 `GetLastResult()`）；
3. 以后接 CI（命令行跑编辑器执行 `Dura.GASValidate`）不用改任何代码。

> 这是一次很典型的重构：**当你发现"两个入口需要同一份能力"时，把能力下沉到 Subsystem/Service 层**。在编辑器开发里，UEditorSubsystem 就是这个 Service 层的标准载体。

Slate 控件订阅子系统广播时的生命周期保护（避免悬空回调）：

```cpp
// Construct：订阅
CachedSubsystem = Subsystem;
ValidationDelegateHandle = Subsystem->OnValidationCompleted.AddRaw(this, &SGasValidatorPanel::HandleValidationCompleted);

// 析构：解除（面板可能比子系统先死）
SGasValidatorPanel::~SGasValidatorPanel()
{
    if (UGasValidatorSubsystem* Subsystem = CachedSubsystem.Get())
    {
        Subsystem->OnValidationCompleted.Remove(ValidationDelegateHandle);
    }
}
```

## 4. 三个控制台命令

注册在模块 cpp 里（`FAutoConsoleCommand`），给自动化测试和 CI 用：

| 命令 | 作用 |
|---|---|
| `Dura.GASValidate` | 完整流水线：扫描 → 报告写日志 → Markdown 报告导出到 Saved/GASValidator/。若资产注册表还在初始化（`-ExecCmds` 启动期触发）会自动延迟 15 秒 |
| `Dura.GASValidatorOpen` | 打开校验器面板 |
| `Dura.GASValidatorExport` | 导出最近一次结果 |

配合命令行启动可以做全自动验证（我们实测用的就是这招）：

```
UnrealEditor.exe Dura.uproject -ExecCmds="Dura.GASValidatorOpen,Dura.GASValidate"
```

编辑器起来后自动打开面板、自动扫描、自动导出报告，全程无需人工点击，结果去 `Saved/Logs/Dura.log` 和 `Saved/GASValidator/` 里看。

## 5. 导出报告的实现

`ExportReport()` 生成 Markdown 文本写到 `Saved/GASValidator/GAS校验报告_时间戳.md`：

```cpp
FFileHelper::SaveStringToFile(Report, *FilePath, FFileHelper::EEncodingOptions::ForceUTF8);
```

- 选 `Saved/` 而不是项目根目录：Saved 是"生成物"的标准位置，不会被 git 追踪，多跑几次不会污染仓库；
- `ForceUTF8`：报告里有中文，不带 BOM 的 UTF8 保证 Markdown 渲染器正常；
- 放在子系统而不是面板：导出和界面无关，命令行 CI 也要用。

导出的报告长这样：

```markdown
# GAS 配置校验报告

- 时间：2026-08-30 03:07:40
- 扫描资产：58
- 错误：0 / 警告：1 / 提示：7
- 耗时：0.39 秒

- **⚠️ 警告** | 数据资产 | `DA.IconMissing` | **DA_AbilityInfo**：第 8 条（…）没有配置 Icon…
- **ℹ️ 提示** | 成本与冷却 | `GA.NoCooldownGE` | **GA_EnemyFireBolt**：该敌人技能没有配置…
```

## 6. 界面打磨细节

- **严重度图标不用 emoji**：第一版用了 ❌⚠️ℹ️，实测编辑器默认字体渲染成方块（豆腐块）。改成「● 错误 / ● 警告 / ● 提示」纯文本 + 颜色，兼容性最好。**编辑器 UI 慎用 emoji**。
- **扫描时给反馈**：点扫描弹 `FScopedSlowTask` 进度条（58 个资产只要 0.4 秒，但用户需要"按钮生效了"的确认感）。
- **导出/未扫描时的引导**：没扫过就点导出，右下角弹通知"还没有扫描结果，先点开始扫描"，而不是静默失败。
