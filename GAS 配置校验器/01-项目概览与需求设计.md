# 01 - GAS 配置校验器：项目概览与需求设计

> 这是「制作过程」系列的第 1 篇。读完你会知道：这个工具是干什么的、为什么值得做、它检查哪些问题、整体架构长什么样。

---

## 1. 这个工具是什么

**GAS 配置校验器**是一个虚幻引擎编辑器插件（C++ Editor 模块），装在 GAS_Dura 项目里。

它做一件事：**点一下按钮，扫描项目里全部 58 个 GAS 相关资产（技能蓝图、效果蓝图、数据资产、曲线表），自动找出配置错误和可疑配置，列成一张表**。每条问题都会告诉你：

- 哪个资产出了问题
- 是什么问题（用大白话解释后果，比如"技能命中后不会造成任何伤害"）
- 该去哪里改（提示你打开蓝图的哪个属性）
- 双击问题行，直接打开对应资产

**一句话总结它的价值**：GAS 的配置错误有个讨厌的特点——**配错时不报错，只有玩到那一刻才会发现"技能放不出来/不掉血/不耗蓝"**。这个工具把"玩到才知道"变成"点一下就知道"。

## 2. 为什么值得做（简历视角）

写 gameplay 代码证明你"会实现功能"；写编辑器工具证明你"理解引擎"。做这个工具需要用到：

| 能力 | 在工具里的体现 |
|---|---|
| UE 模块系统 | Editor 模块与 Runtime 模块分离，打包游戏不包含工具代码 |
| 反射系统 | 用 `FindFProperty` 读取引擎/C++ 类里 `protected` 的属性 |
| 资产管线 | 用 AssetRegistry 枚举资产、加载蓝图 CDO（类默认对象） |
| GAS 架构 | 深入理解 GA/GE/Tag/曲线表之间的咬合关系才能定义规则 |
| Slate UI | 从零搭一个带列表、过滤、搜索、跳转的面板 |
| 编辑器扩展 | 标签页注册、工具栏按钮、EditorSubsystem、控制台命令 |
| 软件工程 | 数据层/逻辑层/界面层分离、误报治理、报告导出（可接 CI） |

## 3. 需求定义（开发前定的标准）

- **技术形态**：C++ Editor 模块（不是蓝图 Editor Utility），因为要简历含金量
- **只报告，不修复**：工具列出问题、能跳转到资产，但绝不改任何资产数据（安全第一）
- **中文界面**：给中文团队/自己用
- **误报优先级最高**：宁可少报，不能乱报。一条误报会让人从此不信任整个工具（后面第 5 篇会讲我们真实消灭的 3 类误报）

## 4. 校验规则清单（v1.0 共 16 条）

规则按类别分组。严重度分三级：**错误**（运行时必出 bug）、**警告**（大概率有问题）、**提示**（值得知道）。

### 4.1 成本与冷却（核心规则）

| 规则 ID | 严重度 | 检查什么 |
|---|---|---|
| `GA.NoCostGE` | 警告 | 玩家主动技能没配 Cost GE → 施放不耗蓝 |
| `GA.NoCooldownGE` | 警告/提示 | 非被动技能没配 Cooldown GE（敌人技能降级为提示，因为敌人普攻没冷却很正常） |
| `GE.CostNoManaModifier` | 错误 | Cost GE 里没有修改 Mana 属性的条目 → 技能实际免费 |
| `GE.CostZero` | 警告 | Cost GE 的 1 级蓝耗数值为 0（本项目蓝耗存负数，取绝对值判断） |
| `GE.CooldownPolicyWrong` | 错误 | 冷却 GE 的持续时间策略不是 Has Duration → 冷却瞬间结束 |
| `GE.CooldownDurationZero` | 警告 | 冷却 GE 的 1 级持续时长为 0 |
| `GE.CooldownNoGrantedTag` | 错误 | 冷却 GE 没有授予任何 GameplayTag → 冷却结束监听不到，**技能永久卡死**（本项目 WaitCooldownChange 靠"Tag 被移除"恢复技能） |

### 4.2 引用完整性

| 规则 ID | 严重度 | 检查什么 |
|---|---|---|
| `GA.NoDamageEffectClass` | 错误 | 伤害技能没配 DamageEffectClass → 打人不掉血 |
| `GE.DamageNoExec` | 错误 | 被用作伤害 GE 的资产没挂 `ExecCalc_Damage` 执行计算器 → 伤害公式不运行 |
| `GE.Empty` | 警告 | 一个 GE 没有任何持续时间、修改器、执行器、授予标签 → 空壳废件 |
| `Asset.LoadFailed` | 错误 | 资产加载失败（文件损坏/引用丢失） |

### 4.3 标签一致性

| 规则 ID | 严重度 | 检查什么 |
|---|---|---|
| `GA.DamageTypeInvalid` | 错误 | 伤害技能的 DamageType 标签没设置 |
| `GA.DamageTypeNotDamage` | 错误 | DamageType 不是 Damage 系列标签 → ExecCalc_Damage 按标签读 SetByCaller 数值会读空，伤害恒 0 |
| `DA.AbilityTagInvalid` | 错误 | DA_AbilityInfo 条目的 AbilityTag 无效 |
| `DA.AbilityTagDuplicate` | 错误 | DA_AbilityInfo 里 AbilityTag 重复 → 查询永远命中第一条 |
| `DA.CooldownTagMismatch` | 警告 | 条目填的 CooldownTag 和它技能的冷却 GE 实际授予的标签对不上 → 技能菜单刷新冷却失效 |
| `DA.CooldownTagMissing` | 提示 | 冷却 GE 授予了标签但条目没填 CooldownTag |

### 4.4 数据资产（DA_AbilityInfo / DA_CharacterClassInfo）

| 规则 ID | 严重度 | 检查什么 |
|---|---|---|
| `DA.EntryMissingAbility` | 错误 | 条目没配技能类 |
| `DA.IconMissing` / `DA.BackgroundMissing` | 警告/提示 | 图标/背景材质没配 → 菜单显示空白 |
| `DA.LevelRequirementInvalid` | 警告 | 等级需求 < 1 |
| `CCI.*` 系列 | 错误/警告 | DA_CharacterClassInfo 的主属性 GE、出生技能、经验曲线等 8 项没配 |
| `GA.NotRegistered` | 提示 | 玩家主动技能没登记进 DA_AbilityInfo/DA_CharacterClassInfo → 技能菜单里看不到它 |

### 4.5 数值曲线

| 规则 ID | 严重度 | 检查什么 |
|---|---|---|
| `GA.DamageCurveRowMissing` | 错误 | 伤害 FScalableFloat 引用的曲线行不存在 → 伤害取值退化为 0 |
| `GA.DamageZero` | 警告 | 伤害基础值为 0 且没配曲线 |
| `GE.ModifierCurveRowMissing` | 错误 | GE 修改器引用的曲线行不存在 |
| `CCI.XPRewardCurveMissing` | 错误 | 经验奖励曲线行不存在 → 击杀不掉经验 |

## 5. 整体架构

```
┌─────────────────────────────────────────────────────┐
│                    编辑器（宿主）                      │
│                                                     │
│  工具栏按钮「GAS 校验」──┐                            │
│  窗口菜单「GAS 配置校验器」┤→ 打开标签页                │
│  控制台 Dura.GASValidate ─┘    │                    │
│                                ▼                    │
│                    ┌───────────────────┐            │
│                    │ SGasValidatorPanel │  ← 界面层  │
│                    │  (Slate 面板)      │            │
│                    └────────┬──────────┘            │
│                             │ 订阅广播 / 调用扫描      │
│                             ▼                       │
│                  ┌─────────────────────┐            │
│                  │ UGasValidatorSubsystem│ ← 服务层  │
│                  │  StartScan()         │            │
│                  │  ExportReport()      │            │
│                  │  OnValidationCompleted│           │
│                  └────────┬────────────┘            │
│                           │ 调用                     │
│                           ▼                         │
│                  ┌─────────────────────┐            │
│                  │  FGasValidatorCore   │ ← 逻辑层   │
│                  │  RunValidation()     │            │
│                  │  16 条规则           │            │
│                  └────────┬────────────┘            │
│                           │ 读取                     │
│                           ▼                         │
│                  ┌─────────────────────┐            │
│                  │  AssetRegistry +     │ ← 数据层   │
│                  │  蓝图 CDO / 数据资产  │            │
│                  └─────────────────────┘            │
└─────────────────────────────────────────────────────┘
```

**三层各管各的**：

- **逻辑层**（`GasValidatorCore.h/.cpp`）：只负责"扫描+判定"，完全不碰 UI。以后想接命令行 CI，直接调它。
- **服务层**（`GasValidatorSubsystem.h/.cpp`）：编辑器子系统（UEditorSubsystem）。按钮、控制台命令、面板共用它的 `StartScan()`；扫描完广播结果，谁关心谁来听。结果也存在它身上，面板关了再开还能显示上一次结果。
- **界面层**（`SGasValidatorPanel.h/.cpp`）：Slate 面板，只做"展示 + 收集点击"，自己不跑任何校验逻辑。

## 6. 代码文件地图

```
Source/DuraEditor/
├── DuraEditor.Build.cs        ← 模块的"购物清单"（依赖哪些引擎模块）
├── DuraEditor.h/.cpp          ← 模块入口：注册标签页 + 工具栏按钮 + 控制台命令
├── GasValidatorTypes.h        ← 数据结构：一条问题长什么样、一次扫描的结果长什么样
├── GasValidatorCore.h/.cpp    ← 校验核心：收集资产 + 16 条规则（本工具的心脏）
├── GasValidatorSubsystem.h/.cpp ← 编辑器子系统：扫描入口 + 结果存储 + 报告导出
└── SGasValidatorPanel.h/.cpp  ← Slate 界面：按钮/列表/过滤/搜索/双击跳转
```

项目文件改动只有两处：

- `Dura.uproject`：Modules 数组里新增了 `DuraEditor`（Type: Editor）
- 新增整个 `Source/DuraEditor/` 目录

**运行时代码（Source/Dura）一行都没动**——工具对游戏本身零侵入。

## 7. 最终实测结果（本项目）

```
扫描 58 个资产 | 错误 0 | 警告 1 | 提示 7 | 耗时 0.39 秒

警告 1 条：
  DA.IconMissing —— DA_AbilityInfo 第 8 条（Abilities.Passive.ListenForEvent）没有配 Icon

提示 7 条：
  6 条 GA.NoCooldownGE —— 敌人技能没配冷却（合理设计，仅提示）
  1 条 DA.BackgroundMissing —— 同一条目的背景材质没配
```

这个结果和人工核对的真实情况一致：这个课程项目本身的配置是健康的，剩下 1 警告 7 提示都是真实存在的"没配完"的地方，**没有一条误报**。
