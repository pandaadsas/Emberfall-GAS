# 09 - 关键 UE 概念通俗解释

> 「原理精讲」第 4 篇。这个工具用到的每个引擎概念，做成一张张"名词卡片"：**它是什么（大白话）→ 在本工具里怎么用 → 在哪个文件能看到**。面试被追问时，这些卡片就是你的弹药库。

---

## 卡片 1：模块（Module）

**大白话**：UE 代码的打包单元。每个模块编译成一个 DLL，模块之间靠"声明依赖"（Build.cs）互相引用。你项目里的 `Source/Dura` 是一个模块，新写的 `Source/DuraEditor` 是另一个。

**类型决定命运**：`Runtime` 模块进游戏包；`Editor` 模块只在编辑器里存在，打包时整个跳过。**这就是"工具不污染游戏"的机制保证**，不是靠自觉，是编译系统物理隔离。

**在哪看**：`Dura.uproject` 的 Modules 数组；`Source/DuraEditor/DuraEditor.Build.cs`。

**面试点**：为什么 Editor 工具必须独立模块？——依赖方向（Runtime 不能依赖 UnrealEd）+ 打包隔离 + 职责边界。

---

## 卡片 2：CDO（Class Default Object，类默认对象）

**大白话**：每个 UClass 出生时都会自带一个"标本实例"。你在蓝图 Class Defaults 里看到/改的那些默认值，物理上就存在 CDO 身上。全世界的 GA_FireBolt 实例，出厂设置都来自这一个对象。

**本工具的核心依赖**：校验器从不创建技能实例，**只读 CDO**——因为配置错误就藏在默认值里：

```cpp
const UGameplayAbility* CDO = GeneratedClass->GetDefaultObject<UGameplayAbility>();
// CDO->GetCostGameplayEffect() 就是你在蓝图 Class Defaults 里看到的那个 Cost GE
```

**在哪看**：`GasValidatorCore.cpp` 第 1 步加载分组。

**面试点**：读蓝图配置不需要实例化、不需要进入世界，CDO 让"静态扫描"成为可能。

---

## 卡片 3：AssetRegistry（资产注册表）

**大白话**：引擎的"资产户口本"。编辑器启动时会后台扫描所有 .uasset，把每个资产的**名字、路径、类型、依赖**记成索引（FAssetData）。它让"不打开资产就能问问题"：

```cpp
AssetRegistry.GetAssetsByPath("/Game/Blueprints/AbilitySystem", AllAssets, /*递归*/ true);
```

**两个层次别搞混**：
- `FAssetData` = 户口条目（轻量，没加载资产）；
- `AssetData.GetAsset()` = 真正把资产加载进内存（重操作，本工具扫 58 个花了 0.4 秒）。

**在哪看**：`GasValidatorCore.cpp` 第 0 步；`SGasValidatorPanel.cpp` 的跳转定位。

**面试点**：编辑器工具做批量资产处理，第一句话就该是"用 AssetRegistry 枚举，再按需加载"。

---

## 卡片 4：反射（Reflection / UPROPERTY 系统）

**大白话**：UE 给每个 `UCLASS()`/`UPROPERTY()` 生成了"自我描述数据"——字段叫什么、什么类型、在内存里第几字节。所以运行时能**按名字**找到并读写字段，哪怕它是 `protected` 的（反射数据不关心访问级别，访问级别只是 C++ 编译期的规则）。

**本工具的两处使用**：

```cpp
// ① 读项目类的 protected 成员（DamageEffectClass / DamageType / Damage）
const FClassProperty* Prop = FindFProperty<FClassProperty>(Obj->GetClass(), TEXT("DamageEffectClass"));
return Prop ? *Prop->ContainerPtrToValuePtr<UClass*>(Obj) : nullptr;

// ② 读引擎类的 protected 成员（FGameplayEffectModifierMagnitude::ScalableFloatMagnitude）
```

**为什么不用指针强转/内存偏移**：反射由 UHT（UnrealHeaderTool）生成并随类布局自动更新，比手算偏移安全；并且全部调用带空指针保护——**属性改名时规则安静跳过，而不是崩溃**。

**在哪看**：`GasValidatorCore.cpp` 顶部的 `ReadClassProperty / ReadTagProperty / ReadScalableFloatProperty / GetScalableFloatFromMagnitude`。

**面试点**：反射是 UMG/序列化/GC/网络同步的基石；工具开发里它是"读取他人类内部数据的正道"。

---

## 卡片 5：Slate 与 SNew 语法

**大白话**：UE 的 C++ UI 框架，编辑器整个就是 Slate 写的。语法是声明式嵌套（详见 08 篇第 1 节）。

**和 UMG 的关系**：UMG 是 Slate 的游戏向封装（有可视化 Designer）。编辑器工具只能用 Slate。

**在哪看**：`SGasValidatorPanel.cpp` 的 `Construct()`。

---

## 卡片 6：EditorSubsystem（编辑器子系统）

**大白话**：UE 官方的"编辑器级全局单例"模板。继承 `UEditorSubsystem` 的类，编辑器启动时自动创建、关闭时自动销毁，全工程任何地方 `GEditor->GetEditorSubsystem<T>()` 一行拿到。

**解决什么问题**：多个入口（按钮/命令/面板）需要共享同一份能力和数据时，把能力放进子系统，大家调它。

```cpp
// 任何地方：
if (UGasValidatorSubsystem* S = GEditor->GetEditorSubsystem<UGasValidatorSubsystem>())
    S->StartScan();
```

**在哪看**：`GasValidatorSubsystem.h/.cpp`；面板和 DuraEditor.cpp 的命令都在调它。

**同类兄弟**：`UEngineSubsystem`（引擎级）、`UGameInstanceSubsystem`（每局游戏）、`UWorldSubsystem`（每个世界）。按生命周期选。

**面试点**：这是 UE5 推荐的全局状态管理方式，替代各种手工 Singleton。

---

## 卡片 7：委托与广播（Delegate / Broadcast）

**大白话**：UE 的事件机制。"广播者"持有一个多播委托，"关心者"把成员函数挂上去；事件发生时广播者一喊，所有挂着的人都收到。

```cpp
// 子系统（广播方）
DECLARE_MULTICAST_DELEGATE_OneParam(FOnValidationCompleted, const FGasValidationResult&);
FOnValidationCompleted OnValidationCompleted;
...扫描完：
OnValidationCompleted.Broadcast(LastResult);

// 面板（接收方）
Handle = Subsystem->OnValidationCompleted.AddRaw(this, &SGasValidatorPanel::HandleValidationCompleted);
// 析构时：
Subsystem->OnValidationCompleted.Remove(Handle);
```

**血泪规则**：`AddRaw` 挂的是裸指针回调，**接收方销毁前必须 Remove**，否则广播时回调到已销毁对象 = 崩溃。本工具在面板析构函数里精确退订。

**在哪看**：子系统 cpp 的 `Broadcast`；面板的 `Construct`/析构。

---

## 卡片 8：标签页系统（Tab Spawner / Nomad Tab）

**大白话**：编辑器里每个可停靠面板（内容浏览器、输出日志……）都是一个"标签页"，由 `FGlobalTabmanager` 统一管理。你注册一个"标签页生成器"（TabSpawner），编辑器就自动把它加进窗口菜单，还能记住用户的停靠位置。

```cpp
FGlobalTabmanager::Get()->RegisterNomadTabSpawner(TabId, FOnSpawnTab::CreateRaw(this, &SpawnValidatorTab))
    .SetDisplayName(...).SetGroup(WorkspaceMenu::GetMenuStructure().GetToolsCategory());
```

**Nomad** = 不依附资产/关卡的独立页（对比：蓝图编辑器的页签依附蓝图资产）。

**在哪看**：`DuraEditor.cpp` 的 `StartupModule` / `SpawnValidatorTab`。

---

## 卡片 9：ToolMenus（菜单/工具栏扩展）

**大白话**：编辑器菜单和主工具栏也是"数据驱动"的——所有菜单项都是 ToolMenus 系统里的条目，任何模块都能 `ExtendMenu("LevelEditor.Toolbar")` 往里塞自己的按钮。

**时序要点**：模块加载早于菜单系统初始化，所以挂按钮必须包在 `UToolMenus::RegisterStartupCallback` 里（"菜单就绪后请回调我"）。退出时对称清理。

**在哪看**：`DuraEditor.cpp` 的 `RegisterMenus()`。

---

## 卡片 10：控制台命令（FAutoConsoleCommand / ExecCmds）

**大白话**：编辑器内置命令行（输出日志面板的 Cmd 输入框，或 ` 键呼出），一行一个命令。C++ 里一行宏就能注册新命令：

```cpp
static FAutoConsoleCommand Cmd(
    TEXT("Dura.GASValidate"), TEXT("说明"),
    FConsoleCommandDelegate::CreateStatic(&RunValidatorScanWhenReady));
```

**`-ExecCmds` 启动参数**：`UnrealEditor.exe Dura.uproject -ExecCmds="A,B"` 让编辑器开机自动执行命令——这就是无头（headless）自动化测试的入口。本工具的 `Dura.GASValidate` 配合它实现"启动→扫描→导报告"全自动。

**坑**：ExecCmds 触发时机早于资产注册表扫描完成，所以命令里要判断 `IsGathering()`，没就绪就挂 Ticker 延迟（05 篇的 Ticker bug 也发生在这）。

---

## 卡片 11：FScalableFloat 与曲线表

**大白话**：FScalableFloat = "一个数，可选地随等级变化"。字段语义：

```
最终值(Level) = Value × 曲线表[行名].Eval(Level)
```

- 没配曲线 → 恒等于 Value；
- 配了曲线（CT_SpellCost 的 "FireBolt" 行）→ 按等级查曲线再乘 Value。

**本工具的坑与对策**：值可能是负数（成本 GE 惯例，游戏侧取 Abs）——判断"没配数值"要判 `IsNearlyZero(Abs(x))` 而不是 `<= 0`（05 篇误报 2 的完整故事）。

**在哪看**：`GasValidatorCore.cpp` 的 `EvaluateScalableFloatAtLevel`、`DoesCurveRowExist`。

---

## 卡片 12：GameplayTag 层级匹配

**大白话**：GameplayTag 是"点分字符串树"（`Damage.Fire` 是 `Damage` 的孩子）。`MatchesTag(父)` 是"你是这家的人吗"，`HasTagExact` 是"你本人是不是他"。

**本工具的选择**：
- DamageType 校验用 `MatchesTag(Damage)`——家族判断，新增元素类型不用改工具；
- DA 的 CooldownTag 校验用 `HasTagExact`——冷却监听绑定的是那一个具体 Tag，多一层少一层都不行。

**在哪看**：`GasValidatorCore.cpp` 第 2/3 步。

---

## 卡片 13：FTSTicker（延迟/轮询）

**大白话**：编辑器主循环的定时回调。"15 秒后帮我跑一次"：

```cpp
FTSTicker::GetCoreTicker().AddTicker(FTickerDelegate::CreateLambda([](float Dt)
{
    DoSomething();
    return false;   // false = 跑完注销；true = 下个周期再来（忘写 = 无限重复！）
}), 15.f);
```

**在哪看**：`DuraEditor.cpp` 的 `RunValidatorScanWhenReady`（ExecCmds 早期触发的兜底延迟）。

## 面试串联模板

被问"介绍你做的编辑器工具"时的一分钟版本：

> "我为项目的 GAS 系统写了一个配置校验器，独立 Editor 模块。它用 AssetRegistry 枚举全部技能/效果资产，读蓝图 CDO 的配置，跑 16 条静态规则——比如冷却 GE 必须授予 Tag（否则技能永久卡死）、DamageType 必须是 Damage 家族标签（否则伤害恒 0）。界面是 Slate 面板，扫描逻辑放在 UEditorSubsystem 里，面板和控制台命令走同一条路径，还支持 -ExecCmds 无头扫描导出 Markdown 报告。开发里最有意思的坑是项目把蓝耗存成负数，我的'小于零报错'规则误报了四条——工具的规则必须和游戏运行时的消费约定对齐。"
