# 10 - 如何自己加一条新规则（实战教程）

> 「原理精讲」第 5 篇。手把手带你往校验器里加一条新规则。学完这个流程，这个工具对你来说就是"可以一直长高的框架"，而不是"一个成品"。

---

## 先学一个思维模板：怎么"发明"一条规则

每条规则都来自同一个问题的答案：**"游戏运行时谁会消费这个配置？消费失败是什么现象？"**

```
第 1 步 找消费方：这个配置在 C++ 里被谁读？（搜代码）
第 2 步 定故障：读不到/读错时，游戏出什么 bug？
第 3 步 定强度：必坏 → 错误；大概率坏 → 警告；只是不推荐 → 提示
第 4 步 定豁免：哪些情况下"看起来错其实对"？（敌人技能、被动技能、运行时赋值的字段…）
第 5 步 写判定：读 CDO 上的值，比较，AddIssue
第 6 步 验证：故意配坏一个资产 → 必须报；恢复 → 必须消失
```

第 4 步和第 6 步最容易被忽略，**而误报几乎都出在这里**（05 篇的三例误报全是死在这两步）。

## 实战示例：加一条"被动技能必须有授予 Tag 的 GE"规则

我们以一个真实有价值的新规则为例走完全程。

### 需求分析（走模板）

这个项目的被动技能（`UDuraPassiveAbility`）靠 `PassiveNiagaraComponent` / `PassiveGameplayEffectComponent` 应用一个**持续的 GE**（比如光环减伤）来生效。GE 靠什么挂在角色身上？靠 **Granted Tags 让 ASC 认领它**（Apply 被动 GE 时常配 `Abilities.Passive.xxx` 标签用于去重/管理）。

- **第 1 步 消费方**：被动技能的激活逻辑、以及去重判断
- **第 2 步 故障**：其实被动 GE 没有授予 Tag 也能跑——所以这条定为 **Info（提示）** 级别："建议检查"
- **第 3 步 强度**：Info
- **第 4 步 豁免**：只查路径含 Passive 的 GA 所引用的 GE
- **第 6 步 验证方案**：把 GA_HaloOfProtection 引用的 GE 授予 Tag 清空 → 应报；恢复 → 消失

> 注意：本教程选定这条是因为它教学价值高，实际实现约 15 行。

### 第 1 步：在交叉引用表里补一条记录

被动技能应用的 GE 存在蓝图组件配置里，位置较深。为了教学简洁，我们用一条更直接的近似规则：**"GA 目录在 Passive 下，但它的 CostGameplayEffect 位置放了内容"**——不，这条意义不大。我们换一条**既真实又好实现**的：

**新规则 `GA.PassiveStartupMissing`：路径在 Passive_Startup 下的技能，CooldownGameplayEffectClass 和 CostGameplayEffectClass 都不该配**（它们是纯事件驱动的被动，配了也没用，说明复制模板时忘了清理）。

- 消费方：无（这正是问题——配了也不会被消费，属于"死配置"）
- 强度：Info
- 豁免：无（规则本身就是豁免规则的镜像）

### 第 2 步：写代码

打开 `Source/DuraEditor/GasValidatorCore.cpp`，找到第 2 步扫 GA 的循环（搜 `// ---- 冷却 GE ----`），在**该循环的末尾**（Damage 技能专属检查之后）插入：

```cpp
		// ---- 新规则：Passive_Startup 目录的技能不该带成本/冷却（复制模板残留检查） ----
		if (PackagePathContains(AssetData.PackageName.ToString(), TEXT("Passive_Startup")))
		{
			if (GACDO->GetCostGameplayEffect() != nullptr || GACDO->GetCooldownGameplayEffect() != nullptr)
			{
				AddIssue(EGasValidationSeverity::Info, TEXT("GA.PassiveStartupExtra"), TEXT("成本与冷却"),
					AssetData, FullObjectPath,
					FText::FromString(TEXT("该技能位于 Passive_Startup 目录（纯事件驱动被动），"
						"但配置了 Cost/Cooldnown GE：它们不会被消费，疑似复制其他技能模板时忘记清理。")));
				// ↑ 顺手修个拼写：Cooldown 写对，别学我这句注释里的 typo
			}
		}
```

需要的辅助函数（若还没有就加到文件顶部，靠近 `IsEnemyAsset`）：

```cpp
static bool PackagePathContains(const FString& InPackagePath, const TCHAR* InFragment)
{
	return InPackagePath.Contains(InFragment, ESearchCase::IgnoreCase);
}
```

（也可以直接用已有的 `IsPassivePath` 风格写法，保持文件内风格一致。）

### 第 3 步：编译

编辑器必须先关掉（DLL 被锁）：

```
tools\Build_DuraEditor.bat
```

### 第 4 步：正反双向验证（关键！）

**正向（必须报）**：启动编辑器 → 打开校验器 → 扫描。如果 GA_ListenForEvent（Passive_Startup 目录里的技能）真的带了多余 GE，面板应出现一条 `GA.PassiveStartupExtra` 提示。

**反向（必须消失）**：如果没报，两种可能——① 该技能本来就没配（规则正确但没触发样本）；② 你的判定条件写错。区分方法：临时把一个被动技能的 Cost GE 随便配一个，再扫描，应出现提示；配回去，提示消失。**只验证"报得出来"、不验证"消得下去"，是校验规则最常见的半成品状态。**

### 第 5 步：更新文档

把新规则加进 `01-项目概览与需求设计.md` 的规则清单表（ID、严重度、检查内容），保持文档与代码同步。

## 再给三个"练习题"（按难度递增）

以下都是这个项目里真实存在的校验需求，你可以照着上面的模板自己实现：

### 练习 1（简单）：`DA.InputTagDuplicate`

DA_AbilityInfo 里两条目配了**相同的 InputTag**（运行时会把两个技能装到同一个快捷栏槽位，后者顶掉前者）。
提示：仿照 `DA.AbilityTagDuplicate` 的 `TMap<FString,int32>` 写法，把检查字段从 AbilityTag 换成 InputTag，注意先判 `IsValid()` 再判重。

### 练习 2（中等）：`GE.DurationPolicyMatch`

所有 GE_PrimaryAttributes_*（角色属性初始化 GE）应该是 `Infinite` 策略；GE_HitReact 应该是 `HasDuration`。
提示：这需要"按资产名/目录猜测用途"——用 `FPaths` 风格的路径前缀匹配（`/Effects/`、`/Enemy/Effects/`），或者更好：建一张"前缀 → 应有策略"的小配置表。想一想报错文案怎么写才不冤枉人。

### 练习 3（困难）：`GA.MontageSocketValid`

伤害技能 `FTaggedMontage` 数组里配置的攻击蒙太奇，其动画通知里引用的 CombatSocket（武器插座名）必须真实存在于对应角色的骨骼上。
提示：这要跨"GA 蓝图 → AnimMontage → AnimNotify → 骨骼"四层资产追引用，是真正的管线级检查。做完这条，工具的含金量再上一个台阶。

## 加规则的通用检查清单（贴在显示器上）

```
□ 找到了消费方代码（能说清"配错会出什么现象"）
□ 严重度有依据（必坏=错误 / 大概率=警告 / 仅建议=提示）
□ 豁免场景想全了（敌人/被动/运行时赋值/历史遗留目录）
□ 报错文案包含：哪里错 + 后果 + 怎么修
□ 编译通过
□ 正向验证：故意配坏 → 必须报
□ 反向验证：修复后 → 必须消失
□ 规则表文档已更新
```
